# 腾讯 TEG 芯片验证实习 一面面经

> 来源：小红书 | 部门：云架构平台部 | 岗位：硬件开发-芯片验证方向
>
> 投递：2025-02-28 | 面试：2025-03-01 | 时长：30分钟

【面试结构】

▸ Part 1：个人信息闲聊（前 5 分钟）

院校背景、实习地点和时间想法、家乡等。

▸ Part 2：培养潜力考察

| 问题 | 要点 |
|------|------|
| 验证工程师的核心能力是什么 | 开放题 |
| 给一个 IP 做验证，做到什么程度才算出口标准（验证完备性） | 核心问题 |
| 如何制定自己的 testcase | 方法论 |

▸ Part 3：八股与项目

▸ 项目

- 项目里 IP 是自研的还是采购的
- 为什么项目中用到了 AHB 和 AXI 两种总线
- **AHB_lite 和 AHB 总线接口的区别**（候选人当时以为二者是同一种协议，事后查证）：
  - AHB_lite 是 AHB 的简化版本
  - 只支持一个主设备
  - 无需仲裁器
  - 仅支持递增突发

▸ AXI 总线

- 乱序和交织的概念：
  - **乱序（Out-of-Order）**：从设备可以按任意顺序返回响应，不需要按主设备发送请求的顺序；主设备通过 ID 信号将请求和响应匹配
  - **交织（Interleaving）**：从设备可以交错返回多个传输请求的数据，通常用于 burst 传输，允许从设备在返回一个请求的数据时插入另一个请求的数据
- AXI 中写地址信号是谁发出的
- CPU 是否一定是 master
- AXI 协议中五个通道的关系
- AXI 中数据传输方式有哪些类型

▸ UVM

因时间不够面试官没有深入问（仅了解程度考察）。

▸ Part 4：反问

- 腾讯验证实习生 hc 数量？（不方便透露）

- 公司更青睐什么样的实习生 → **更看重有培养潜力的候选人**，没做过相关项目也没关系

【关键收获】

- 腾讯芯片验证偏向考察**验证思维**（完备性、testcase 制定），而非纯八股
- AHB_lite ≠ AHB，是简化版
- AXI 乱序/交织是高频考点，要能清晰解释
