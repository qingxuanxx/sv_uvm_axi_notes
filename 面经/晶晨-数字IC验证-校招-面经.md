# 晶晨 IC验证岗面经

> 来源：小红书 | 面试全部围绕 AXI 协议的深度验证，均为场景化问题

---

## 场景化问题

| 问题 | 考察点 |
|------|------|
| 如何编写约束限制激励不跨越 4KB 边界 | 约束写法：地址 + burst 长度联合约束 |
| 是否测试过 AXI 死锁场景，下游持续不返回数据时如何通过 timeout 机制防止挂死 | 死锁/超时 |
| 乱序返回的控制方式、乱序程度的控制逻辑 | outstanding/乱序深度控制 |
| 参考模型中对乱序的处理逻辑 | 模型如何对齐乱序响应 |
| 参考模型对异常地址检查的实现方式 | 地址解码/错误路径 |
| 反压场景的验证方法 | ready 拉低时机 |
| 下游激励侧乱序的实现逻辑 | 从机乱序响应模型 |
| 下游 valid 延迟随机为相同值时的现象与影响 | 同步化随机导致的关联性陷阱 |

---

## 关键收获

- 晶晨是**场景题重度用户**：全部问题围绕 AXI 深度验证展开
- 4KB 边界约束：`addr + size*len <= 4K 对齐边界` 的联合约束写法
- "valid 延迟随机为相同值"的陷阱：多个通道共用同一随机源导致关联——激励要独立随机
- timeout 机制是验证环境必备（防挂死），面试官会问"你加了没有"
