# AMBA AHB 学习笔记：从第一笔传输到 AHB5

这是一份可以从头读下去的协议学习笔记，而不是信号名称和规则的提纲。我们先跟着读写传输经过地址阶段和数据阶段，再逐渐加入流水线、等待状态、HTRANS、burst、互联和错误响应，最后学习
AHB5 扩展。

本文依据 Arm《AMBA AHB Protocol Specification》IHI
0033C。采用新版术语 Manager 和 Subordinate。旧资料中的
Master 和 Slave 指相同角色，但旧版完整 AHB 的 SPLIT、RETRY
不能搬进 IHI 0033C：这里的 HRESP 只有 OKAY 和 ERROR。

验证内容只放在能够帮助理解协议的位置。学习目标不是先写 UVM，而是看到任意一个
HCLK
上升沿时，能说清上一笔数据阶段是否完成、当前地址阶段是否接受、数据属于哪一个地址，以及下一周期哪些信号必须保持。

| 术语 | 含义 |
|---|---|
| Manager | 发起地址和控制，例如 CPU、DMA |
| Subordinate | 响应访问，例如 SRAM、外设接口 |
| transfer | 一个地址阶段加对应的数据阶段 |
| beat | burst 中的一笔 transfer |
| 有效传输 | HTRANS 为 NONSEQ 或 SEQ |

## 1. 为什么 AHB 要把一次传输拆成两个阶段

如果 CPU
必须等上一笔数据返回以后才能给出下一个地址，地址译码、存储器和返回通路会轮流空闲。AHB
把传输拆成地址阶段与数据阶段，并让后一笔地址与前一笔数据重叠，以提高持续吞吐量。

地址阶段原则上占一个 HCLK 周期。数据阶段可以占一个或多个周期，由 HREADY
决定何时完成。所谓零等待，是数据阶段没有额外延长，并不表示地址和数据在同一个阶段完成。

同一周期的 HADDR 可能属于传输 B，而 HWDATA、HRDATA、HRESP 和
HREADY 属于传输 A。任何波形分析都必须先建立地址到数据的阶段映射。

## 2. 系统中的 Manager、Subordinate 和 Interconnect

Manager 产生地址、方向、大小和 burst 属性。Subordinate
接收被译码的请求并返回读数据、完成状态或错误。Interconnect
负责地址译码、返回多路选择，在多 Manager 系统里还负责仲裁。

协议规定接口行为，但不限定互联内部必须采用哪一种拓扑。单 Manager 系统常见
decoder 加 mux；多 Manager 系统可能采用矩阵或分层互联。

每个 Subordinate 有自己的 HSELx 和
HREADYOUT。互联把当前数据阶段目标的
HRDATA、HRESP、HREADYOUT 路由给 Manager。全局 HREADY
不是所有从机 ready 的简单与运算。

## 3. 最小信号集合

第一次看波形，先盯住
HADDR、HTRANS、HWRITE、HSIZE、HWDATA、HRDATA、HREADY

HREADY 是接口统一前进条件。在 HREADY 为 HIGH

## 4. 零等待读传输

Manager 在 T0 之后驱动地址
A、HTRANS=NONSEQ、HWRITE=LOW 和

HRDATA(A)、HRESP=OKAY 和
HREADYOUT=HIGH；Manager 在 T2 上升沿采样。

A 的数据阶段里可以同时出现 B 的地址阶段。没有下一笔时，Manager 通常驱动
IDLE。

## 5. 零等待写传输

写地址和对应写数据不在同一阶段。Manager 先给出 A 的地址与
HWRITE=HIGH，A 被接受后，才在随后的数据阶段驱动 HWDATA(A)。

如果 T1 到 T2 是 A 的写数据阶段，同一时间的 HADDR 可能已经是
B。Subordinate 不能拿 HADDR(B) 去解释 HWDATA(A)。

若实现 HWSTRB，它与 HWDATA 同相位。写被等待时，HWDATA 和有效
HWSTRB 都必须保持到完成。

## 6. 流水线的吞吐和延迟

第一笔传输仍经历地址与数据两个阶段。流水线填满以后，A 数据与 B 地址、B 数据与 C
地址依次重叠，零等待时可以每周期完成一笔。

高吞吐不等于单笔延迟消失。分析性能时要区分首笔延迟、持续吞吐和等待状态造成的停顿。

监视器应在地址接受时保存描述符，在数据完成时把数据和响应附到该描述符上，不能按同周期信号直接拼接。

## 7. HREADY 和等待状态

Subordinate 用 HREADYOUT
拉低延长当前数据阶段。互联选择当前目标的返回，形成 Manager 看到的
HREADY，并把 HREADY 反馈给所有相关接口。

HREADY=LOW
时，当前数据阶段没有完成；流水线中的下一地址阶段也未被接受。HREADY 重新为
HIGH 的上升沿才真正推进。

读数据只要求在最终完成周期有效。写数据由 Manager 提供，所以等待期间必须稳定。

## 8. HTRANS 的四种类型

IDLE 表示没有有效传输；BUSY 表示 burst 仍会继续，但 Manager
暂时不能发出下一拍；NONSEQ 表示单笔或 burst 第一拍；SEQ 表示
burst 后续拍。

IDLE 和 BUSY 不产生数据阶段。Subordinate 必须忽略并提供零等待
OKAY。BUSY 不是从机忙，也不是 HREADY 的替代品。

SEQ 的控制属性延续上一拍，地址通常按 HSIZE 递增；WRAP burst
到达边界时回卷。

## 9. 等待期间允许的 HTRANS 变化

把 HREADY=LOW 简化成所有地址控制绝对保持会遗漏规范例外。被等待的 IDLE
可以变成 NONSEQ；固定长度 burst 的 BUSY 可以变成 SEQ。

不定长 INCR 的 BUSY 可以变成 SEQ 继续，也可以变成 IDLE 或
NONSEQ 终止原 burst。

一旦 HTRANS 变成真正需要执行的 NONSEQ 或 SEQ，就必须保持到
HREADY 为 HIGH。其他地址控制也要满足相应稳定要求。

## 10. HSIZE、地址对齐和窄传输

HSIZE 表示每拍传输的字节数，而不是物理数据总线宽度。它不能超过
DATA_WIDTH，并在整个 burst 内保持不变。

所有有效传输按大小对齐：halfword 要求 HADDR[0]=0，word 要求
HADDR[1:0]=00，doubleword 要求 HADDR[2:0]=000。

窄传输只使用宽数据总线中的部分 byte
lane。地址低位和端序决定有效通道，参考模型最好按字节保存数据。

## 11. HBURST 与递增地址

SINGLE 是一拍；INCR 是不定长；INCR4、8、16
是固定长度递增；WRAP4、8、16 是固定长度回卷。

burst 第一拍为 NONSEQ，后续有效拍为 SEQ。固定长度 burst
必须完成规定拍数并以 SEQ 结束，不能以 BUSY 结束。

Manager 不得发起跨越 1KB 地址边界的递增 burst。这与最小地址译码区域为
1KB 相配合。

## 12. WRAP burst 的边界

回卷窗口大小等于 beats 乘以 bytes_per_beat。先向下对齐求
boundary_base，再在该窗口内对偏移做模运算。

WRAP 不是简单回到
start_address，而是越过窗口末尾时回到包含起始地址的窗口基址。

正确公式是 boundary_base + ((start -
boundary_base + n*size) mod boundary_size)。

## 13. OKAY、等待和 ERROR

等待没有独立响应编码。尚未完成时，Subordinate 使用
HRESP=OKAY、HREADYOUT=LOW；成功完成时使用 OKAY、HIGH。

ERROR 必须用两个响应周期：第一周期
HRESP=ERROR、HREADYOUT=LOW；第二周期仍为 ERROR，但
HREADYOUT=HIGH。

两周期 ERROR 给 Manager 时间取消流水线中已经广播的后继地址。读
ERROR 时不能依赖 HRDATA 阻止副作用，规范建议把 HRDATA 驱为零。

## 14. 地址译码和返回选择

decoder 在地址阶段产生 HSELx。返回 mux
必须把选择信息延迟到对应数据阶段，否则下一地址会让返回通路过早切换。

数据阶段 A 与地址阶段 B 重叠时，返回 mux 仍选择 A 的
Subordinate，而 decoder 可以已经为 B 产生另一个 HSEL。

单个 Subordinate 的最小地址空间是 1KB，并以 1KB 边界开始和结束。

## 15. 默认 Subordinate

地址图没有完全填满时必须有默认 Subordinate。不存在地址上的 NONSEQ 或

## 16. HPROT 与内存类型

HPROT 描述指令或数据、特权级、可缓冲、可修改以及可选的 cache

存在。接口属性决定可选端口。

## 17. HNONSEC 与安全访问

AHB5 的 Secure_Transfers 属性引入 HNONSEC。LOW 表示
Secure，HIGH 表示 Non-secure。

安全权限通常由互联或目标检查。属性必须与地址阶段一起被接受，并与同一笔传输对应。

安全错误最终仍通过协议响应返回，但权限策略本身属于系统实现。

## 18. HWSTRB

HWSTRB 每一位对应 HWDATA 的一个字节通道，是与 HWDATA
同相位的可选数据阶段信号。

全零 HWSTRB 是允许的，表示这一拍不更新任何字节。落在非活动 byte lane
的 strobe 被忽略。

HWSTRB 可以逐拍变化；HSIZE 则在 burst 中保持。HWSTRB[n]
总对应 HWDATA[(8n)+7:(8n)]，这一物理对应与端序无关。

## 19. 数据总线、端序和宽度

AHB 使用分开的 HWDATA 和 HRDATA。协议允许 8 到 1024
位的若干二次幂宽度，推荐最小宽度为 32 位。

little-endian、byte-invariant big-endian 和
word-invariant big-endian 对地址与 byte lane
的映射不同。

宽度转换组件必须保持地址、大小、响应和副作用。不要用主机语言整数的端序暗中替代协议映射。

## 20. 时钟、复位和信号有效性

HRESETn 是唯一低有效信号，可异步断言，但在 HCLK
上升沿之后同步撤销。组件还应定义最小复位周期数。

复位期间 Manager 应输出 HTRANS=IDLE，Subordinate 应输出
HREADYOUT=HIGH。

不要求有效的 payload 可以为任意值，但推荐 0 或 X；无效 byte lane
推荐驱动 0，以免事务之间泄漏旧数据。

## 21. 锁定和单副本原子性

HMASTLOCK 表示锁定传输序列。它不等于 AHB5 Exclusive

单副本原子性保证其他观察者不会看到一个原子块被部分更新。实际保证还受到起始地址对齐限制。

byte strobe

## 22. Exclusive Transfer

典型流程是 Exclusive Read、在 Manager 内计算新值、再对同一地址
Exclusive Write。

若期间没有其他 Manager
写该位置，独占写成功并更新；若被干扰，独占写失败且不能更新内存。

Exclusive Transfer 必须是单拍、地址按 HSIZE 对齐、不能包含
BUSY，并使用 HEXCL、HMASTER、HEXOKAY 与 Exclusive
Monitor 协作。

```text
HREADY          [  HIGH    ][   LOW    ][   LOW    ][  HIGH   ]

A               |--地址--| |----------- 数据阶段 ------------|
B                          |----------- 地址阶段被延长 --------|
```

T1 以后 A 已经进入写数据阶段。

T1-T2 和 T2-T3 是等待周期，所以 HWDATA(A) 与 HWSTRB(A) 不能改变。

与此同时，B 的地址阶段也被延长；T4 上升沿才完成 A 并接受 B。

### 图 24-4 两周期 ERROR 响应

```text
上升沿          T0         T1         T2         T3         T4
                |          |          |          |          |
HADDR           [    A     ][       B 保持       ][   ...    ]
HTRANS          [ NONSEQ   ][ NONSEQ   ][       IDLE        ]
HWDATA                      [        Data(A) 保持             ]
HRESP                       [  OKAY    ][ ERROR   ][ ERROR   ]
HREADY                      [   LOW    ][   LOW   ][  HIGH   ]
说明                        额外等待     ERROR 1    ERROR 2
```

如果目标在 ERROR 之前还需要等待，额外等待周期必须使用 HRESP=OKAY。

ERROR 的第一周期是 HRESP=ERROR、HREADY=LOW。

ERROR 的第二周期仍为 ERROR，但 HREADY=HIGH，当前传输在该上升沿以失败结束。

Manager 在看到第一个 ERROR 周期后，可以把已经广播的 B 改成 IDLE。

### 图 24-5 返回通路为什么必须按数据阶段选择

```text
                     地址阶段选择
HADDR -------------> Decoder ----------> HSEL_SRAM / HSEL_TIMER
                                              |
                                              | 延迟到对应数据阶段
                                              v
SRAM.HRDATA  -------+
SRAM.HRESP   -------+\
SRAM.HREADYOUT -----+ \
                       >---- Return Mux ----> HRDATA/HRESP/HREADY
TIMER.HRDATA -------+ /
TIMER.HRESP  -------+/
TIMER.HREADYOUT ----+
```

当 A 的数据阶段与 B 的地址阶段重叠时，Decoder 可以正在译码 B，
但 Return Mux 必须仍选择 A 对应的 Subordinate。

因此，HREADY 是当前数据阶段目标返回的结果，不是“所有 HREADYOUT 必须同时为 HIGH”。

## 29. 常见误区

### 29.1 “零等待只有一个周期”

这句话不准确。正确理解是：仍有地址和数据两个阶段。

自检时给场景增加一笔后继传输和两个等待周期。如果原解释不能准确指出地址接受边沿与数据完成边沿，就应重新画流水线。

### 29.2 “HREADY 是所有 HREADYOUT 相与”

这句话不准确。正确理解是：互联选择当前数据阶段目标的返回。

自检时给场景增加一笔后继传输和两个等待周期。如果原解释不能准确指出地址接受边沿与数据完成边沿，就应重新画流水线。

### 29.3 “写地址和写数据同时采样”

这句话不准确。正确理解是：对应 HWDATA 在随后的数据阶段。

自检时给场景增加一笔后继传输和两个等待周期。如果原解释不能准确指出地址接受边沿与数据完成边沿，就应重新画流水线。

### 29.4 “BUSY 表示从机忙”

这句话不准确。正确理解是：BUSY 是 Manager 的 burst 内停顿。

自检时给场景增加一笔后继传输和两个等待周期。如果原解释不能准确指出地址接受边沿与数据完成边沿，就应重新画流水线。

### 29.5 “等待时所有信号绝对不变”

### 29.6 “ERROR 可以单周期”

## 32. 总结：用四个问题读任何 AHB 波形

- 上一笔数据阶段是否在这个 HREADY=HIGH 的上升沿完成？

- 当前 HTRANS 对应的地址阶段是否在这个上升沿被接受？

- 当前 HWDATA、HRDATA、HRESP 属于此前哪一笔地址？

- 如果 HREADY=LOW，下一周期哪些信号必须保持，是否存在 IDLE/BUSY
  例外？

能稳定回答这四个问题以后，再去记 burst
编码、内存属性或独占访问就不会变成孤立知识点。AHB
的所有复杂规则最终都围绕流水线身份、阶段推进和系统可见性展开。
