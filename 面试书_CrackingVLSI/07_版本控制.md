# 版本控制 学习笔记（Cracking VLSI 第7章）

> **核心结论**：版本控制系统（VCS）是一个记录你所有工作变更记录的数据库，用于让团队多人协作时把每个人的增量修改同步到公共数据库中。本章覆盖 CVS、GIT、SVN 三大主流版本控制系统的基础命令，其中 GIT 以"分布式 + 全局跟踪整个源码树"成为现代软件与硬件设计的主流选择。
>
> **记忆主线**：概述（什么是 VCS / 为什么需要 / 什么是仓库）→ CVS（add → checkin → checkout → update → tag → diff → log → status）→ GIT（init/clone 建仓 → pull/push 同步 → HEAD 版本追踪 → add/commit 提交 → stash/reset 撤销 → log/blame/diff/mv 查询管理）→ SVN（trunk/branch/tag 概念 → update vs commit → 常用命令 → G/R 状态码）。

---

> 来源：《Cracking Digital VLSI Verification Interview》(Ramdas Mozhikunnath & Robin Garg)，原书第 7 章为英文问答形式，本笔记为翻译 + 结构化整理。

## 7.1 概述（General）

### 什么是版本控制系统（Version Control System）？
版本控制系统本质上是一个**数据库**，它存储你所有工作的**变更记录（change records）**。

### 为什么需要版本控制系统？
当一个团队的多个成员在同一个共享项目上协作时，关键是要把每个成员的**增量修改**同步到一个公共数据库中。版本控制系统通过把作者的增量修改（连同作者姓名、修改内容和注释）更新到公共数据库来实现这一点，其他人随时可以访问这些信息。

> 记忆：VCS 解决的三大问题 = **多人协作同步** + **修改可追溯（谁改的、改了啥、为什么改）** + **历史可回溯**。

### 常见的版本控制系统有哪些？
- **CVS**（Concurrent Versions System，并发版本系统）
- **GIT**
- **SVN**（Subversion，颠覆版本系统）
- **Perforce**（P4）等

### 什么是仓库（repository）？
仓库是**集中存放和维护所有数据/代码的中心位置**，项目中所有文件和目录（即整个项目的组成部分）都存储在这个中央存储区里。

> 记忆：repository = 项目的"中央档案馆"，所有文件、目录、历史版本都在里面。

## 7.2 CVS（Concurrent Versions System）

### CVS 是什么？
CVS 全称 **Concurrent Versions System（并发版本系统）**，是一种常用的、**免费**的版本控制系统。

### 如何向 CVS 数据库添加新文件/目录？
```bash
cvs add <filename>
```
把指定的 `<filename>` 加入 CVS 数据库。**注意**：`add` 只是登记文件名，之后还需要 "checkin"（检入）才能真正把文件内容更新到数据库中。

### 如何把文件检入（check-in）到 CVS 数据库？
添加文件名后，用以下任一命令把文件放入数据库：
```bash
cvs checkin -m "message_here" <filename>
cvs ci     -m "message_here" <filename>   # ci 是 checkin 的简写
cvs commit -m "message_here" <filename>   # commit 是 checkin 的另一种写法
```
- `-m "message_here"`：**消息选项**，用于填写关于本次变更的简短说明。
- 一个文件可以检入任意多个版本，**每次检入都会生成一个新的版本号**。

### 如何从 CVS 数据库检出（checkout）文件？
```bash
cvs checkout <filename>   # 或简写：cvs co <filename>
```
- `<filename>` 可以是文件，也可以是目录（目录则检出该目录下所有文件）。
- 默认总是取文件**最新版本**；要取指定版本，用版本号参数：
```bash
cvs co -r <version_number> <filename>
```

### 如何把工作环境更新到数据库的最新状态？
检出一批文件后，其他用户可能修改了中央数据库中的文件，你需要定期把这些变更同步到自己的工作区：
```bash
cvs update <filename>   # 或简写：cvs up <filename>
```
`update` 的工作方式与 checkout 类似，会把 CVS 中已更新但尚未同步到你工作环境的文件更新过来。

### 什么是打标签（tagging）？如何给文件打标签？
**Tagging（打标签）**是版本控制系统非常实用的功能：多人共享项目数据库时，你可能希望在固定节点打"检查点"（例如项目达到中间里程碑时）。可以给数据库里不同版本的所有相关文件关联**同一个标签**，之后随时通过标签名把它们取回。

```bash
cvs tag <filename>
```

### 如何按标签检出模块中的一组文件？
想从仓库中取出带某个标签的所有文件：
```bash
cvs co -r <tag> <module_name>
```

### 如何删除标签？
```bash
cvs rtag -d <tagname> <filename>
```
（`rtag` 用于在仓库端直接操作标签，`-d` 表示删除。）

### 如何查看两个不同版本文件的差异？
```bash
cvs diff -r <version1> -r <version2> <filename>
```

### 如何查看文件的检入日志信息？
检入时用 `-m` 填写的日志消息，可以通过下面命令查看：
```bash
cvs log <filename>
```

### 如何查看文件的状态？
查看文件是否与中央数据库同步、或是否已被本地修改：
```bash
cvs status <filename>
```

### 如何同时查看标签信息与状态？
```bash
cvs status -v <filename>
```
（`-v` 选项在状态中附带显示标签信息。）

> 记忆：CVS 命令速记 = add（登记）→ checkin/ci/commit（入库）→ checkout/co（取文件）→ update/up（同步）→ tag/rtag（打标签/删标签）→ diff/log/status（比较/日志/状态）。

## 7.3 GIT（重点，现代主流）

### GIT 是什么？
GIT 是**应用最广泛的开源版本控制系统**，同时用于软件开发与硬件设计，**免费**，并且是**分布式（distributed）修订控制系统**。

### GIT 相比 CVS 的优势是什么？
CVS 只跟踪**单个文件**的变更，而 GIT 以**全局视角跟踪整个源码树（source tree）**。

| 对比维度 | CVS | GIT |
|---|---|---|
| 跟踪粒度 | 只跟踪单个文件的变更 | 以全局视角跟踪整个源码树 |
| 架构 | —（集中式思路，按文件操作） | 分布式修订控制系统 |
| 定位 | 常用、免费 | 最广泛使用的开源 VCS，软硬件开发通用 |

### 创建仓库：git init 与 git clone
```bash
git init                    # 初始化/创建一个 GIT 仓库
git clone <repository_to_be_cloned>   # 克隆远程仓库，作为个人开发/修改的本地仓库
```
> 记忆：**init 空手建仓**（本地从零开始），**clone 复制建仓**（从已有仓库拷一份下来开发）。

### 同步更新：git pull 与 git push
```bash
git pull <repository_from_which_updates_are_to_be_fetched>   # 从其他仓库拉取最新更新
git push                                                    # 把你的修改发布给团队
```
> 记忆：**pull = 拉（收别人改的），push = 推（发自己改的）**，一进一出。

### GIT 如何跟踪当前检出的版本？—— HEAD
GIT 通过 **HEAD** 跟踪你当前检出的版本：HEAD 指向一个**分支（branch）**，分支中包含一个 **SHA1 哈希**。查看该信息的命令：
```bash
git head
```
> 注意：本书原文使用 `git head` 查看 HEAD 信息；实际 GIT 中常见写法是 `git rev-parse HEAD` 或 `git log` 等命令来查看当前 HEAD 指向的提交哈希。

### 如何重命名文件？
两步过程：
```bash
git mv <filename> <new_filename>   # 第一步：移动/重命名文件
git commit <new_filename>          # 第二步：提交新文件名
```

### 查看历史与追责：git log 与 git blame
```bash
git log <filename>     # 查看某文件/目录的提交历史
git blame <filename>   # 逐行查看"谁修改了该行"的详细信息
```
> 记忆：**log 看"何时提交过"，blame 看"每一行是谁写的"**。

### 差异比较：git diff
```bash
git diff <commit1> <commit2>   # 显示两个 commit 或分支之间的差异
```

### 撤销与暂存：git reset / git stash / git add
```bash
git reset <filename>     # 撤销本地仓库中对某文件所做的修改
git stash                # 在 pull/merge 或切换分支之前，临时保存当前修改
git add <filename(s)>    # 把自上次 commit 以来的修改移入暂存区（staging area）
```
> 记忆：**reset 扔掉修改，stash 暂存到一边（之后还能取回），add 把修改放入暂存区准备提交**。

### 提交修改：git commit
```bash
git commit -m "first commit"   # 把暂存区的修改存入仓库，并附带消息（如 "first commit"）
```

### 回滚已推送（public）的提交
```bash
git revert HEAD~2..HEAD   # 回滚最近两次已推送公开的提交
```
> 注意：`revert` 用于**已推送并公开**的提交——它不是删除历史，而是生成一个反向的新提交来撤销改动，从而保持历史安全。

> 记忆：GIT 工作流主线 = **clone/init（建仓）→ add（暂存）→ commit（提交）→ push（发布）/ pull（同步）→ log/blame/diff（查询）→ reset/stash/revert（撤销回滚）**。

## 7.4 SVN（Subversion）

### SVN 是什么？
SVN 全称 **Subversion**，是一个**开源**版本控制系统。

### SVN 中 Trunk、Branch、Tag 分别是什么？
| 概念 | 含义 |
|---|---|
| **Trunk（主干）** | 开发的主体，从项目开始一直延续到项目结束的主线开发线 |
| **Branch（分支）** | 从 trunk 的某个点派生出的代码副本，用于进行重大修改，同时保护 trunk 中代码的完整性 |
| **Tag（标签）** | trunk 或 branch 上某个你希望保留的**时间点**，类似重大发布后对代码做基线（baselining） |

> 记忆：**Trunk 是主线，Branch 是岔路（改完可以并回主线），Tag 是拍照留念（某个时刻的冻结快照）**。

### Update 与 Commit 的区别是什么？
| 操作 | 方向 | 作用 |
|---|---|---|
| **Update** | 仓库 → 本地 | 用团队成员提交到仓库的修改**更新本地工作区** |
| **Commit** | 本地 → 仓库 | 把本地修改**推送到仓库** |

> 记忆：**Update 是"下载"，Commit 是"上传"**，方向相反。

### 常用命令：svn add / svn mkdir / svn diff
```bash
svn add <file_or_directory_name>      # 添加文件或目录
svn mkdir <new_directory_name>        # 创建新目录
svn diff <filename>                   # 查看本地版本与仓库版本的差异
```

### 状态码 G 和 R 表示什么？
| 状态码 | 含义 |
|---|---|
| **G** | 仓库上的改动已**自动合并（merged）**到工作副本中 |
| **R** | 该项已在工作副本中被**替换（replaced）**：原文件已被标记/安排删除，同时一个同名新文件被安排添加以取代它 |

### 如何从 trunk 创建新 tag？
```bash
svn copy http://example.svn.com/.../repo/trunk http://example.svn.com/.../repo/tags/new_tag -m "creating a new tag from trunk"
```
（用 `svn copy` 把 trunk 复制到 tags 目录下，即完成打标签。）

### Revert 的作用是什么？
**Revert（还原）**会**移除你的本地修改**，并从仓库重新加载最新版本。
```bash
svn revert <filename>
```

> 记忆：SVN 关键点 = **三个目录（trunk/branch/tag）+ 两个方向（update/commit）+ 两个状态码（G 合并 / R 替换）+ revert 清空本地改动**。

## 本章总结

### 学习重点排序

| 优先级 | 内容 | 说明 |
|---|---|---|
| ★★★ | GIT 全流程命令 | 现代主流（init/clone/add/commit/push/pull/log/blame/diff/reset/stash/revert/mv），面试高频 |
| ★★★ | 版本控制系统基本概念 | VCS 定义（变更记录数据库）、必要性（多人同步）、repository 定义 |
| ★★ | GIT 与 CVS 的对比 | CVS 只跟踪单文件，GIT 全局跟踪整个源码树、分布式 |
| ★★ | SVN 的 trunk/branch/tag | 主干/分支/标签的概念区分与用途 |
| ★★ | SVN update vs commit | 方向相反的两个基本操作 |
| ★ | CVS 基础命令 | add/checkin/checkout/update/tag/diff/log/status（了解即可） |
| ★ | SVN 其他命令与状态码 | svn add/mkdir/diff/copy/revert，状态码 G 与 R |

### 最重要的 10 条规则

| # | 规则 |
|---|---|
| 1 | 版本控制系统是一个存储所有变更记录的数据库，核心价值是团队增量修改的同步与追溯。 |
| 2 | 仓库（repository）是集中存放项目所有文件、目录与历史数据的中央存储区。 |
| 3 | CVS 中 add 只是登记，必须 checkin（ci/commit）才能把文件内容真正入库，每次 checkin 产生新版本号。 |
| 4 | checkout 默认取最新版本，指定版本用 `-r <version_number>`；`update` 用于把仓库最新改动同步到本地。 |
| 5 | 打标签（tag）可把不同版本的文件关联到同一检查点，之后用 `-r <tag>` 整体取回。 |
| 6 | GIT 是分布式系统，用 HEAD（指向分支，含 SHA1 哈希）跟踪当前检出的版本。 |
| 7 | GIT 工作流主线：add 暂存 → commit 提交 → push 发布，pull 拉取他人更新。 |
| 8 | git log 看提交历史，git blame 逐行查"谁改的"，git diff 比较 commit/分支差异。 |
| 9 | SVN 中 trunk 是开发主线，branch 用于重大修改而保护 trunk，tag 是时间点快照（基线）；update 是从仓库下载，commit 是向仓库上传。 |
| 10 | SVN 状态码 G 表示自动合并，R 表示项被替换；revert 会移除本地修改并重新加载仓库最新版本。 |
