# 计算机体系结构 学习笔记（Cracking VLSI 第 2 章）

> **核心结论**：现代数字 IC 设计已全面转向 SoC（片上系统），验证工程师每天面对的都是"CPU + 各种外设/存储器"的系统，因此必须掌握计算机体系结构的基础知识——从指令集架构（RISC/CISC）、流水线（pipeline）与冒险（hazard），到存储层次（cache、虚拟内存、TLB）、缓存一致性（MESI）以及中断异常机制。本章的目的不是教你设计处理器，而是让你理解体系结构，从而能设计出正确的验证场景（激励、约束、参考模型与断言）。
>
> **记忆主线**：指令集架构（RISC/CISC）→ 处理器结构（冯·诺依曼/哈佛、寄存器）→ 流水线与冒险 → 存储层次（SRAM/DRAM、Cache 映射与替换、写策略、一致性协议）→ 虚拟内存（分页、TLB、页错误）→ 中断/异常 → 性能增强技术（超标量、乱序执行、分支预测）→ I/O 与编码技巧。

## 一、指令集架构：RISC 与 CISC

### Q1. RISC 与 CISC 的区别

**RISC**（Reduced Instruction Set Computing，精简指令集计算）与 **CISC**（Complex Instruction Set Computing，复杂指令集计算）是两大指令集设计哲学。

| 对比维度 | RISC | CISC |
|---|---|---|
| 指令数量 | 少，指令简单 | 多，指令复杂 |
| 指令长度 | 固定长度（fixed length） | 可变长度（variable length） |
| 寻址方式 | 少 | 多 |
| 硬件复杂度 | 简单硬件，强调软件 | 复杂硬件（解码复杂指令），强调硬件 |
| 代码规模 | 指令条数多，需要更多 RAM 存储程序 | 指令条数少，代码紧凑，占 RAM 少 |
| 执行周期 | 通常 1 个时钟周期完成 | 视复杂度可能需要多个时钟周期 |
| 流水线 | 因单周期指令，可流水线化 | 难以流水线化 |
| 性能优化目标 | 减少每条指令的周期数（cycles per instruction） | 减少每个程序的指令条数（instructions per program） |
| 访存模型 | Load/Store 型：访存只能通过 load/store 指令 | 支持 memory-to-memory 操作 |

**典型例子**：将内存 M1、M2 两个数相乘并把结果写回 M1——

- CISC：一条指令 `MULT M1, M2` 即可完成"读内存 → 运算 → 写回内存"。
- RISC：需要多条指令：`LOAD A, M1` → `LOAD B, M2` → `PROD A, B` → `STORE M1, A`。

> **记忆**：CISC 把"复杂"放进硬件，RISC 把"复杂"交给软件。RISC 靠"每条指令更快"取胜，CISC 靠"每条程序更短"取胜。
>
> **注意**：现代高级微架构中，很多 CISC 实现（如 x86）内部也会先把复杂指令翻译成简单微指令（micro-ops）再执行，所以两者的界限在实际实现中已模糊。

## 二、处理器结构：冯·诺依曼与哈佛架构

### Q2（上）. 冯·诺依曼（Von Neumann）架构
- 数据与指令共用**单一存储器**，CPU 到存储器之间只有**一条总线**同时访问数据和指令。
- 采用**统一 cache**（数据和指令混用）。

### Q2（下）. 哈佛（Harvard）架构
- 数据与指令**分开存储**，有**两条独立总线**可同时访问指令存储器和数据存储器。
- 采用**分离的指令 cache 和数据 cache**。

| 对比 | Von Neumann | Harvard |
|---|---|---|
| 存储器 | 单一存储器存数据和指令 | 数据和指令分开存储 |
| 总线 | 单总线，指令/数据竞争带宽 | 双总线，可并行取指和取数 |
| Cache | 统一 cache | 指令/数据分离 cache |
| 年代 | 较老 | 现代计算机大多基于此 |

> **记忆**：哈佛="分家"（数据和指令分居两室、各有通道），冯·诺依曼="合住"（一间房、一条走廊）。
>
> **注意**：书中强调现代多数计算机架构基于哈佛结构，原因之一是可并行取指与取数，减少总线冲突。

## 三、数据表示：大小端（Endianness）

### Q3. Little Endian 与 Big Endian

**端序（endian-ness）** 指字节在存储器中的存放顺序（同样适用于数字传输系统中字节的发送顺序）。内存通常是字节可寻址（byte addressable）的，而多数架构按 32 位（4 字节）字长操作，因此把字写入字节寻址内存时有两种方式：

1. **Big Endian（大端）**：字的**最高有效字节（MSB）** 存在**较小的地址**。
2. **Little Endian（小端）**：字的**最低有效字节（LSB）** 存在**较小的地址**。

**示例**：CPU 把字 `0xDDCCBBAA` 写入起始地址 `0x1000`（占用 0x1000 ~ 0x1003）：

| 地址 | Big Endian | Little Endian |
|---|---|---|
| 0x1000 | DD（MSB） | AA（LSB） |
| 0x1001 | CC | BB |
| 0x1002 | BB | CC |
| 0x1003 | AA | DD |

> **记忆**：大端"大头（MSB）在前"（低地址），小端"小头（LSB）在前"。x86 用小端，网络协议多规定大端（网络字节序）。
>
> **注意**：验证中经常遇到跨端序场景（CPU 写、外设读，或反之），地址/数据字节序转换是常见验证点。

## 四、存储器基础：SRAM 与 DRAM

### Q4. SRAM 与 DRAM 的区别

- **DRAM**（Dynamic RAM，动态随机存取存储器）：数据以**电荷**形式存储在**电容**中，每个存储单元由 **1 个晶体管 + 1 个电容**构成。由于电容会漏电，DRAM 是易失性器件，必须**周期性刷新**（refresh）才能保持数据。
- **SRAM**（Static RAM，静态随机存取存储器）：只要供电就能保持数值，是静态的。无需刷新，因此比 DRAM **更快**。每个存储单元由 **6 个晶体管**构成（vs DRAM 的 1T1C），因此**单位成本更高**。

| 对比 | SRAM | DRAM |
|---|---|---|
| 存储原理 | 锁存器/触发器结构保持 | 电容电荷保持 |
| 单元结构 | 6 个晶体管（6T） | 1 晶体管 + 1 电容（1T1C） |
| 是否需要刷新 | 否 | 是（电荷会泄漏） |
| 速度 | 快 | 慢 |
| 密度/成本 | 低密度、高成本 | 高密度、低成本 |
| 典型用途 | Cache（高速） | PC 主存（高密度） |

> **记忆**：SRAM 用"电路状态"存数据，DRAM 用"电荷"存数据——电荷会跑，所以要刷新。cache 要快所以用 SRAM，主存要容量大所以用 DRAM。

### Q5. 相关计算：地址位数

**题目**：计算机内存为 256KB，按字节寻址需要多少位地址？
**解答**：256KB = 2^8 × 2^10 = 2^18 字节 → 需要 **18 位**地址（2^18 个可寻址位置）。

> **记忆**：地址位数 = log2(可寻址单元数)。1K=2^10、1M=2^20、1G=2^30，256=2^8，加总即得。

## 五、CPU 内部寄存器

### Q6. CPU 中的寄存器类型

1. **程序计数器 PC（Program Counter）**：保存**当前正在执行指令的地址**。
2. **指令寄存器 IR（Instruction Register）**：保存**当前正在执行的指令**（即 PC 所指地址处的取值）。
3. **累加器（Accumulator）**：保存处理器内部算术/逻辑运算的**中间结果**。
4. **通用寄存器（General Purpose Registers, GPR）**：保存程序所需的任意临时数据，数量由架构定义，软件（汇编器）可在程序执行中用于存放临时数据。**通用寄存器越多，CPU 执行越快**（减少访存）。
5. **栈指针寄存器 SP（Stack Pointer）**：特殊用途寄存器，保存**栈顶**（最近一次压栈条目）的地址。栈最典型的用途是保存**子程序调用的返回地址**。

> **记忆**：PC 指路（下一条指令地址）、IR 拿货（当前指令）、ACC 算账（中间结果）、GPR 装货（临时数据）、SP 顶天（栈顶）。
>
> **注意**：PC 实际是指向"当前正在执行"指令的地址，取指完成后会自增指向下一条。

## 六、流水线（Pipeline）

### Q7. 流水线概念

**流水线**是在单个处理器内实现一种并行——**指令级并行（ILP）**——的技术：把基本指令周期拆成一系列步骤（称为流水线级）。与"一条指令完全执行完再取下一条"的顺序方式不同，流水线把每条指令拆成一段段步骤，让**不同指令的不同步骤并行执行**（前一条未完成就开始下一条）。

- **提高指令吞吐率（throughput）**：同一时刻执行多个操作。
- **不降低指令延迟（latency）**：单条指令从开始到结束仍需走完所有步骤。

**示例**：指令生命周期可分成 5 级——取指（Fetch）、译码（Decode）、执行（Execute）、访存（Memory access）、写回（Write back），处理器可同时处理多条指令。

> **记忆**：流水线像工厂流水线——单件产品完成时间不变（latency 不变），但单位时间产出变多（throughput 提升）。

### Q8. 流水线冒险（Pipeline Hazard）

**冒险**：程序中下一条指令因某种原因无法继续执行的情况。共有三类：

1. **结构冒险（Structural Hazard）**：**资源冲突**阻碍了重叠执行。例如设计只有 1 个浮点执行单元且每次执行需 2 个时钟周期，那么程序中连续两条浮点指令就会让流水线停顿（stall）；另一类常见冲突资源是**内存/cache 访问**。
2. **数据冒险（Data Hazard）**：指令依赖前一条指令的结果，而这种依赖被流水线的重叠执行暴露出来。分三种：
   - **RAW（Read after Write，写后读）**：本指令需要读的源操作数，被前一条指令写入。
   - **WAW（Write after Write，写后写）**：本指令写入的寄存器，前一条指令也写入。
   - **WAR（Write after Read，读后写）**：本指令写入的寄存器，是前一条指令的源操作数。
3. **控制冒险（Control Hazard）**：由**分支（branch）和跳转（jump）指令**改变程序执行顺序所引起。

> **注意**：RAW 是真实的数据依赖（必须解决）；WAW/WAR 在乱序执行的机器中才会出现（顺序执行的流水线里天然不会发生）。

### Q9. 各类冒险的消除/规避技术

| 冒险类型 | 常用技术 |
|---|---|
| 结构冒险 | **复制资源**实现并行执行：分离指令 cache 和数据 cache、整数与浮点各配多个执行单元、分离 load/store 单元等 |
| 数据冒险 | **乱序执行**（Out-of-order execution）：互不依赖的指令可在依赖指令停顿期间继续执行；**数据前递/转发**（Data forwarding）：针对 RAW，把前一条指令的写结果直接转发给后面依赖的指令，消除冒险 |
| 控制冒险 | **分支预测**（branch prediction）算法：预测分支结果，从而在分支后取到正确的指令序列 |

> **记忆**：结构冒险靠"多备资源"，数据冒险靠"乱序 + 前递"，控制冒险靠"分支预测"。

### Q10. 流水线计算题

**题目**：一台流水线机器有 10 级，每级处理一个数据元素需 1ns，假设无冒险，处理 100 个数据元素需要多少时间？
**解答**：第 1 个元素走完 10 级需 10 × 1ns = 10ns，此时流水线已填满；其余 99 个元素每 1ns 出一个。总时间 = (10 + 99) ns = **109 ns**。

> **记忆**：总时间 = 流水线深度 × 单级时延 + (元素数 − 1) × 单级时延，即"第一个元素的时间 + 其余元素每个一拍"。

## 七、指令寻址方式（Addressing Modes）

### Q11. 常见寻址方式

1. **立即数寻址（Immediate）**：操作数作为**常量**直接包含在指令中。例：`add r0 r1 0x12`（r1 内容加常量 0x12，结果存 r0）。
2. **直接寻址（Direct）**：操作数的**地址**直接写在指令中。例：`load r0 0x10000`（从地址 0x10000 读数据到 r0）。
3. **寄存器寻址（Register）**：操作数放在寄存器中，寄存器名直接作为指令的一部分。例：`mul r0, r1, r2`（r1 × r2，结果存 r0）。
4. **变址寻址（Indexed）**：**索引寄存器内容 + 指令中的偏移量（offset）** 得到有效地址。例：`load r0 r1 offset`（r1 含基地址，"r1 + offset" 为读数据的地址，读入 r0）。

| 寻址方式 | 操作数/地址来源 | 例子 |
|---|---|---|
| 立即数 | 指令内常量 | `add r0 r1 0x12` |
| 直接 | 指令内直接给出地址 | `load r0 0x10000` |
| 寄存器 | 寄存器名 | `mul r0, r1, r2` |
| 变址 | 索引寄存器 + 偏移 | `load r0 r1 offset` |

> **记忆**：立即数=值在指令里；直接=地址在指令里；寄存器=数在寄存器里；变址=寄存器+偏移拼地址。

## Q12. 局部性原理（Locality of Reference）

**局部性原理**：描述"若程序访问了某内存位置，同一位置或附近位置再次被访问的频率"。分两类：

1. **时间局部性（Temporal Locality）**：某个内存位置在某一时刻被引用，则**不久后很可能再次引用同一位置**（如循环中的变量、计数器）。
2. **空间局部性（Spatial Locality）**：某个内存位置被引用，则**不久后很可能引用其附近的内存位置**（如数组的顺序遍历）。

> **记忆**：时间=同一个地址反复用（"再回首"）；空间=附近的地址接着用（"邻居串门"）。Cache 和预取（prefetch）都建立在这两条原理之上。

## 九、存储层次与 Cache

### Q13. 系统中的存储层次

系统中的不同种类存储器（按离 CPU 由近到远/速度由快到慢）：

1. **寄存器（Register）**
2. **Cache**
3. **主存/主存储器（Main/Primary Memory）**
4. **辅存（Secondary Memory，磁/光介质，如磁盘）**

> **记忆**：寄存器（快而小）→ Cache → 主存（DRAM）→ 磁盘（慢而大），越往下容量越大、速度越慢、成本越低。

### Q14～Q15. Cache 的概念与工作原理

**Cache** 是一小片**快速存储器**，位于主存与 CPU 之间（也可做在 CPU 芯片/模块内）。

**工作原理（cache 操作概述）**：CPU 请求某个内存位置的内容时，**先查 cache**：

- 若数据在 cache 中，CPU 直接从 cache 取数（快，无需访问主存）；
- 若不在，则从主存**读一块（block）**到 cache，再按字（word）分块从 cache 送给 CPU。
- Cache 中包含**标签（tag）**，用来标识每个 cache 槽（slot）里存放的是主存的哪一块。

### Q16. Cache 命中与失效（Hit / Miss）

- **Cache Hit（命中）**：在 cache 中查找地址时，cache 含有该内存位置。
- **Cache Miss（失效）**：查找的地址在 cache 中找不到。

### Q17. 链表 vs 向量（数组）：cache 对程序性能的影响

- **链表（linked list）**：元素存储在**非连续**的内存位置。
- **向量（vector/数组）**：元素存储在**连续**的位置。

由于主存到 cache 的搬移通常以 **cache line**（一般 64 或 128 字节）为单位，一旦某位置在 cache 中，**其后的连续字节极可能也在 cache 中**。因此，在带 cache 的机器上，**搜索向量比搜索链表更快**（链表节点跳跃访问，无法利用空间局部性）。

> **记忆**：cache line 是"整块搬运"，所以连续存储（数组）吃香、跳跃存储（链表）吃亏。验证性能测试中，数据布局方式直接影响命中率。

### Q18. Cache 映射方式对比

三种主要映射技术。先决概念：主存与 cache 都被划分为**块（block）**，即 **cache line**（一般 64 字节），是映射的最小单位。

**1. 直接映射（Direct Mapping）**：主存块与 cache 块**一一固定对应**。例：cache 128 块、主存 4096 块——主存块 0→cache 块 0，块 1→块 1，…，块 127→块 127，块 128 又→块 0（取模）。一般化：主存块 **k** → cache 块 **k mod 128**。若块大小 64B、地址 32 位：`地址[5:0]` 索引块内字节，`地址[12:6]` 标识可映射的 cache 块，其余 `地址[31:13]` 作为 **tag 位**与数据一起存于 cache。
- 优点：最简单；知道地址即可算出 cache 中唯一可能的位置，只需与该位置一处 tag 比较即可判断命中/失效。
- 缺点：即使 cache 未满，若访问模式落在同一块映射区（冲突访问），也会导致频繁替换（eviction），效率低。

**2. 全相联映射（Fully Associative Mapping）**：主存**任意块可映射到 cache 任意块**。块大小 64B、地址 32 位时：`地址[5:0]` 索引块内，其余全部 `地址[31:6]` 作为 tag 与数据一起存储。查找任何地址时，需把地址的 `[31:6]` 与 **cache 中所有位置**的 tag 比较——需要**更大的比较器逻辑，功耗更高**。
- 优点：任何主存块可映射到任何 cache 块，**所有位置可被充分利用**。

**3. 组相联映射（Set-Way Associative Mapping）**：把 cache 块**分组为若干组（set）**。例：128 块的 cache 组织成 **64 组 × 每组 2 块**，即 **2 路组相联（2-way set associative）**。主存块**直接映射到某个组**，组内可放入**任意一个块**。32 位地址时：`地址[5:0]` 索引块内字节，`地址[11:6]` 直接映射到 64 个组之一，其余 `地址[31:12]` 作为 tag 随每个 cache line 存储。

| 映射方式 | 主存块→cache 位置 | tag 位（例：32 位地址、64B 块） | 优点 | 缺点 |
|---|---|---|---|---|
| 直接映射 | 固定唯一（k mod N） | 地址[31:13] | 最简单、比较逻辑最小、命中判断快 | 冲突易导致频繁替换 |
| 全相联 | 任意位置 | 地址[31:6] | 利用率最高、无冲突替换 | 需与所有位置 tag 比较，比较器大、功耗高 |
| 组相联 | 固定组 + 组内任意 | 地址[31:12]（2 路、64 组时） | 折中：利用率与硬件复杂度平衡 | 比直接映射复杂 |

> **记忆**：直接映射=固定座位；全相联=随便坐；组相联=先分楼（组）再随便坐。相联度越高，tag 越多、比较越贵。
>
> **注意**：组相联的"组内随便放"需要**组内逐路比较**，所以多路意味着多个 tag 比较器并行。

### Q19. 高相联度的代价

**相联度更高（more associativity）的 cache 有什么缺点？**
需要**更大的比较器**，把进来的地址与组内**所有路（way）的 tag** 逐一比较 → **更多功耗、更多硬件**。

### Q20～Q21. Cache 计算题

**题 1**：字节可寻址 CPU，16 位地址总线，cache 特性：a) 直接映射，每块 1 字节；b) 块索引用 4 位。cache 有多少块？每块需存多少 tag 位？
**答**：索引 4 位 → **16 个块**。16 位地址、块大小 1 字节：`地址[3:0]` 索引 16 个块，剩余 `地址[15:4]` 作为 **tag 位（12 位）**。

**题 2**：4 路组相联 cache，总大小 256KB，每个 cache line 64 字节。cache 中有多少个组？tag 位需多少位？假设地址 32 位。
**答**：总块数 = 256K / 64 = 4096 块；4 路组相联 → 组数 = 4096 / 4 = **1024 组**。32 位地址、64B line：`地址[5:0]` 索引 line 内（6 位），`地址[15:6]` 定位组（10 位），剩余 `地址[31:16]` 为 **tag 位（16 位）**。

> **记忆**：地址三段式——低位块内偏移（block offset，取决于块大小）、中间组索引（set index，取决于组数）、高位 tag（其余全部）。

### Q22. 写策略：Write-thru 与 Write-back

- **写直达（Write Thru）**：每次对 cache 的写操作**同时写入主存**。设计简单，内存始终与 cache 一致；缺点是**写操作一直消耗内存带宽**。
- **写回（Write Back）**：每次写操作**只写 cache**，写主存**推迟到该 cache line 被替换（evict）或丢弃时**。内存带宽利用率更好（数据只在必要时写回）；缺点是若系统中有多个 cache 缓存同一地址，**保持数据一致性更复杂**——因为内存不一定有最新数据。

| 对比 | Write Thru | Write Back |
|---|---|---|
| 写主存时机 | 每次写 cache 都同步写主存 | 延迟到 line 被替换/丢弃时 |
| 设计复杂度 | 简单 | 较复杂（需 dirty 标记等） |
| 内存带宽 | 写操作持续占用 | 只在必要时占用 |
| 多 cache 一致性 | 内存总有最新数据，较简单 | 内存可能过期，需一致性协议配合 |

> **记忆**：Write Thru "即时同步"、Write Back "记账后清算"。现代多级 cache 通常 L1 用 write-thru（保持与 L2 一致）、L2 用 write-back，或用一致性协议管理。

### Q23. 包含（Inclusive）与排他（Exclusive）Cache

适用场景：**多级 cache**（如 L1、L2、L3）设计。

- **严格包含（strictly inclusive）**：L1 中存在的所有地址，**也一定存在于 L2** 中。
- **排他（exclusive）**：同一地址**至多**存在于 L1、L2 之一，**绝不会同时**存在于两者。

| 类型 | 定义 | 优点 |
|---|---|---|
| Inclusive | L1 内容 ⊆ L2 | 多处理器系统中要移除某 cache line 时，**只需查 L2**（L1 必然也在 L2 有记录），操作简单 |
| Exclusive | 两级 cache 之间互不重叠 | **多级 cache 合计可存储更多数据**（不重复存放） |

> **注意**：exclusive 的代价是，检查某 line 是否在缓存中时，**必须同时查 L1 和 L2** 两处。

### Q24. Cache 行替换算法（组相联 cache）

当组内路已满需要装入新行时，选择替换哪一行：

1. **LRU（Least Recently Used，最近最少使用）**：为每个 cache line 关联"age bits"记录使用时间，需要替换时**丢弃最久未使用的行**。
2. **MRU（Most Recently Used，最近最常使用）**：与 LRU 相反，替换**最近使用过**的行。
3. **PLRU（Pseudo LRU，伪 LRU）**：类似 LRU，但不用成本高的 aging bits（在更大、更高相联度的 cache 中成本高），**只用一两个 bit** 记录使用情况，近似 LRU。
4. **LFU（Least Frequently Used，最不经常使用）**：记录每行被**访问的次数**，替换**被访问次数最少**的行。
5. **随机替换（Random）**：不保存任何信息，需要替换时**随机挑一行**。

> **记忆**：LRU 赶走"最久没用"的，MRU 赶走"刚用过的"，PLRU 是 LRU 的低成本近似，LFU 赶走"用得最少"的，Random 全靠运气。验证时可针对替换算法构造特定访问序列测试命中率/替换行为。

## 十、多核系统与 Cache 一致性

### Q25. Cache 一致性问题

在**共享内存多处理器（SMP）系统**中，多个处理器各有自己的 cache，**同一地址（同一数据）的多份拷贝可能同时存在于不同 cache 中**。若允许各处理器自由更新自己的 cache，就会导致**内存视图不一致**——这就是 **cache 一致性问题（cache coherency problem）**。

**示例**：两个处理器被允许写同一地址，那么不同处理器读同一地址可能看到**不同的值**。

### Q26. 监听（Snoop）与目录（Directory）协议

- **监听式一致性协议（Snoop-based）**：某处理器发出数据请求时，**广播给共享系统中所有其他处理器**；每个处理器都"监听（snoop）"该请求，检查自己是否有该数据拷贝并相应回应。即**每个处理器都努力维护一致的内存视图**。
- **目录式一致性协议（Directory-based）**：用**目录（directory）**记录**哪些处理器正在访问/缓存哪些地址**。发起新请求的处理器先查目录，得知**哪个代理有拷贝**，然后向该代理发**点对点（point-to-point）请求**获取最新数据。

| 对比 | Snoop | Directory |
|---|---|---|
| 请求方式 | 广播到所有处理器 | 点对点（查目录后定向请求） |
| 追踪方式 | 每个处理器监听总线 | 中央目录记录各地址的持有者 |
| 特点 | 简单，但总线/网络流量大 | 可扩展性好，适合大系统 |

> **注意**：snoop 靠总线广播，处理器数量多时总线成为瓶颈；directory 以目录查询代替广播，扩展性更好，但需维护目录本身。

### Q27. MESI 协议

**MESI 是带多个 write-back cache 的设计中最常用的一致性协议**。每个 cache line 在各 cache 中都被跟踪一个状态，用于响应 snoop 请求：

1. **M（Modified，已修改）**：该 line 数据**相对主存已被修改**，是脏（dirty）的。
2. **E（Exclusive，独占）**：数据相对主存是**干净的（clean）**，但**仅存在于本 cache**（独占）。独占属性允许本处理器对该 line **执行写操作**。
3. **S（Shared，共享）**：该 line 在**多个 cache 中共享相同值**，且相对主存是干净的。因与所有 cache 共享，协议**不允许写**该 line。
4. **I（Invalid，无效）**：该 line **无效，无有效数据**。

**读写服务规则**：
- 读请求：line 处于**除 Invalid 外的任何状态**都可服务。
- 写请求：只有 line 处于 **Modified 或 Exclusive** 状态才能服务。

> **记忆**：M=脏且私有、E=净且私有、S=净且共享、I=无效。写操作要先拿到"独有权"（M/E），读只要"有效"（非 I）即可。
>
> **注意**：S 状态不允许写——要写必须先把其他副本置为 Invalid（这正是 RFO 干的事，见下文）。

### Q28. MESIF 与 MOESIF 协议

MESI 的两种扩展，引入两个新状态：

**1. F（Forward，转发）**：是 **S 状态的特化形式**，表示该 cache 应作为该 line 的**指定应答者（designated responder）**，负责向新请求**转发数据**。若多个 cache 都以 S 状态持有同一 line，协议指定其中一个为 F，为新处理器发来的请求转发数据。协议保证：**任何 cache 以 S 持有某 line 时，至多还有一个（另一个）cache 以 F 持有它**。
- 作用：**减少发往内存的流量**——没有 F 状态时，即使多个 cache 都以 S 持有某 line，它们**都不能**把数据转发给另一个请求读/写的新处理器（注意：S 状态的行只能服务**本处理器自己**的读请求）。

**2. O（Owned，拥有）**：用于在系统各 cache 之间**搬运已修改（脏）数据而无需写回内存**的特殊状态。若某 line 还同时被其他 cache 以 S 状态共享，则该 line 可从 **M 状态转移到 O 状态**。作用：**把脏数据的写回推迟到真正需要时**。

| 状态 | 含义 | 与 MESI 的关系 |
|---|---|---|
| F | 指定的转发应答者（S 的特化） | MESI + F = MESIF |
| O | 拥有脏数据且被共享，无需写回内存 | MESI + O = MOESI（+F 即 MOESIF） |

> **记忆**：F 是"共享中指定一个发言人"（减少访问内存），O 是"脏数据先在缓存圈内转手"（推迟写回）。

### Q29. RFO（Read for Ownership）

**RFO = Read for Ownership（读以获得所有权）**：一致性协议中的一种操作，**结合了"读"和"作废广播（invalidate broadcast）"**。

- 由试图**写入处于 Shared 或 Invalid 状态的 cache line** 的处理器发出。
- 使**所有其他处理器**把该 line 的状态置为 **I（Invalid）**。
- RFO 事务本质是**带写意图的读操作**，因此是**独占（exclusive）**的：它把数据取入本 cache，同时作废其他所有缓存了该地址的处理器 cache。

> **记忆**：RFO = "我要写，先读来并作废别人"——把 S/I 提升为可写的 M/E 状态。这也是 MESI 中写操作触发的主要事务类型。

## 十一、虚拟内存

### Q30. 虚拟内存概念

**虚拟内存**是一种内存管理技术：**即使实际物理内存很小，也让处理器看到一片虚拟的连续地址空间**。

- **操作系统**管理虚拟地址空间，并负责把辅存（如磁盘）中的内容按需分配到物理主存。
- CPU 中的**地址翻译硬件**——通常称为 **MMU（Memory Management Unit，内存管理单元）**——把虚拟地址翻译为物理地址。
- 翻译基于**分页（paging）**：用一块连续的地址块（称为**页，page**）在虚拟内存与物理内存之间建立映射。

### Q31. 虚拟地址 vs 物理地址

- **虚拟地址（virtual address）**：软件程序/进程在其地址空间中访问内存所用的地址。
- **物理地址（physical address）**：操作系统配合硬件把虚拟地址翻译后，真正用于访问 DRAM 主存位置的地址。
- 翻译用**分页**完成；若主存（DRAM）中没有该位置，则在 **OS 协助下把数据从辅存（如磁盘）搬到主存**。

> **记忆**：虚拟地址是"软件看到的假地址"，物理地址是"硬件真正用的真地址"，MMU 负责翻译，缺页时 OS 从磁盘搬数据。

### Q32. 分页机制（Paging）

- 所有虚拟内存实现都把**虚拟地址空间划分为页**——连续的虚拟地址块。**页是虚拟内存管理中数据在辅存与物理内存之间搬移的最小粒度**。
- 多数系统页大小**至少 4KB**；一些架构在需要更大实存时支持大页（如 1MB 或 4MB）。
- **页表（page table）** 用于把应用程序看到的虚拟地址翻译为物理地址：它是存储**多个页的虚拟地址→物理地址翻译信息**的数据结构。

> **记忆**：页=搬移的最小单位；页表=翻译对照簿。大页减少页表条目数，适合大内存场景。

### Q33. TLB（Translation Lookaside Buffer）

**TLB 是存放"最近虚拟地址→物理地址翻译"的 cache**，用于后续快速取回翻译结果：

- 程序请求一个虚拟地址，若 **TLB 命中**，可直接（像 cache 一样）快速得到物理地址，**无需访问主存**。
- 只有 **TLB 未命中**时，才需要真正访问内存、**逐级遍历页表（page table walk）** 获取翻译——这需要**好几个时钟周期**。

> **记忆**：TLB = "翻译的 cache"。命中快、未命中慢（页表遍历），与 cache 命中/失效的思维完全一致。

### Q34. 页错误（Page Fault）

程序访问一个**已映射进虚拟地址空间、但尚未加载进主存**的内存页时，计算机硬件（MMU）会**触发一个中断**，这个中断就叫 **页错误（Page Fault）**。之后由 OS 负责把该页从辅存调入主存并恢复执行。

> **注意**：页错误是"正常机制"而非错误——它是虚拟内存按需加载（demand paging）的实现手段。

## 十二、中断与异常

### Q35. 如何中断正在执行的任务

CPU 正在执行任务时，可通过**外部中断源（external interrupt sources）**打断它，转而运行另一个任务。

### Q36. 中断（Interrupt）与异常（Exception）的区别

- **中断（Interrupt）**：**异步**事件，通常由**外部硬件**（I/O 设备或其他外设，如键盘、存储设备、USB 口）产生，**与指令执行边界不同步**。中断总是在**当前指令执行完后**才被服务，CPU 跳去执行**中断服务例程（ISR）**。
- **异常（Exception）**：**同步**事件，是处理器**执行指令时检测到预定义条件**而产生的（如除零、未定义指令）。异常进一步分三类，程序流如何改变取决于类型：
  1. **故障（Faults）**：在**出错指令执行之前**被检测并服务（如页错误）。
  2. **陷阱（Traps）**：在**引起陷阱的指令之后**被服务。最常见的陷阱是**用户自定义的调试用中断**（如系统调用、断点）。
  3. **中止（Aborts）**：仅用于**严重的系统问题**，此时执行**无法再继续**。

| 对比 | 中断（Interrupt） | 异常（Exception） |
|---|---|---|
| 同步性 | 异步（外部硬件随时来） | 同步（指令执行中检测到条件） |
| 来源 | I/O 设备、外设 | 指令自身引发（除零、非法指令等） |
| 服务时机 | 当前指令执行完后 | 依类型（fault 在指令前、trap 在指令后、abort 直接终止） |

> **记忆**：中断是"外部敲门"（异步、随机），异常是"内部报警"（同步、由指令触发）。Fault 先处理再执行指令，Trap 执行完再处理，Abort 是"没法继续了"。
>
> **注意**：验证中常见的页错误、总线错误本质上属于 fault/abort 类异常；中断是验证 CPU 与外设交互（DMA、中断响应）的核心场景。

### Q37. 向量中断（Vectored Interrupt）

**向量中断**：**中断设备**向处理器发送中断的同时，附带一个**该中断特有的代码（向量号）**，处理器凭此**直接跳转到正确的 ISR**。

**非向量中断**：第一级 ISR 必须先**读取中断状态寄存器（interrupt status registers）**，解码出到底是哪个中断源引发了中断，再决定执行哪个具体的 ISR。

> **记忆**：向量中断=设备告诉你"该找谁"（带号直达）；非向量中断=自己翻档案（读状态寄存器排查）。
>
> **注意**：向量中断响应更快，但需硬件支持向量号分发；验证中断控制器（interrupt controller）时要覆盖两种模式。

## 十三、取指优化与执行模型

### Q38. 提高指令取指性能的技术

1. **指令 Cache + 预取（Prefetch）**：指令 cache 和预取算法会**提前**于实际的译码、执行阶段持续取指，从而**隐藏取指阶段的内存延迟**。
2. **分支预测 + 分支目标预测**：
   - **分支预测（Branch Prediction）**：基于历史预测条件分支**是否发生（taken / not-taken）**；
   - **分支目标预测（Branch Target Prediction）**：在处理器**计算出目标之前**就预测目标地址。
   - 两者共同**最小化取指停顿**——取指算法可基于预测继续取指。

### Q39. 超标量流水线处理器（Superscalar）

**超标量流水线设计**利用**指令级并行（ILP）**提升处理器性能：**一个时钟周期内同时派发多条指令到不同的执行单元**，从而在一个周期内执行多条指令。若处理器一个周期可并行执行 N 条指令，则称为 **N 路超标量（N-way superscalar）**。

> **记忆**：流水线是"时间上重叠"，超标量是"空间上并列"（多个执行单元同时干活）。

### Q40. 顺序执行 vs 乱序执行

- **顺序执行（In-Order Execution）**：指令**始终按程序中的顺序**取指、执行、完成。**任何一条指令停顿，其后所有指令也跟着停顿**。
- **乱序执行（Out-of-Order Execution）**：指令**按程序顺序取指**，但**执行可以乱序**，**完成（写回）仍按顺序**。优点：**一条指令停顿，其后相互独立的指令仍可继续执行**，从而加速整个程序的执行。

| 对比 | In-Order | Out-of-Order |
|---|---|---|
| 取指 | 程序顺序 | 程序顺序 |
| 执行 | 程序顺序 | 可乱序 |
| 完成/写回 | 程序顺序 | 仍按程序顺序 |
| 停顿影响 | 后继指令全部停顿 | 独立指令可继续执行 |

> **记忆**：乱序执行是"排队取号、叫到才办（按序写回）"，中间可以穿插办其他事。它天然需要处理 WAW/WAR 等额外数据冒险，也依赖重排序缓冲（ROB）保证按序完成。

### Q41. 条件分支与无条件分支

**分支指令**用来把程序流从当前指令切换到另一指令序列，分两类：

- **无条件分支（Unconditional Branch）**：**总是**发生分支。例：`Jump <offset>` —— 执行结果必然使指令序列从 `<offset>` 地址开始。
- **条件分支（Conditional Branch）**：**可能发生也可能不发生**，取决于某个条件。例：`beq ra, rb, <offset>` —— 若两个源寄存器 ra、rb **相等**则跳转到 `<offset>`；不相等则继续按原顺序执行下一条指令。

> **记忆**：无条件=必跳；条件=看条件（如 beq 比较相等才跳）。

### Q42. 分支预测 vs 分支目标预测

- **分支预测器（Branch Predictor）**：预测**分支是否被采用（taken / not-taken）**，从而把正确的指令序列**预取进指令 cache**，避免程序遇到分支指令后取指停顿。
- **分支目标预测器（Branch Target Predictor）**：不同——它在执行单元**计算出分支目标之前**，就预测"被采用的条件分支或无分支指令"的**目标地址**。

| 预测对象 | 预测什么 |
|---|---|
| Branch Prediction | 分支**是否 taken**（取哪一路指令流） |
| Branch Target Prediction | taken 分支的**目标地址**（跳到哪） |

> **注意**：两者配套使用——先猜"跳不跳"，再猜"跳哪去"，共同消除控制冒险带来的取指停顿。

## 十四、I/O 与设计技巧

### Q43. 内存映射 I/O（Memory Mapped I/O, MMIO）

**MMIO** 是 CPU 与 I/O/外设之间进行输入输出的一种方法：**CPU 用同一条地址总线访问内存和 I/O 设备**（设备内部的寄存器或设备内的存储器）。在系统地址映射（address map）中，**为 I/O 设备预留某段内存区域**；当 CPU 访问该地址时，**监视这条地址总线**的对应 I/O 设备就会响应该访问。

**示例**：32 位地址总线的 CPU 可访问 0 ~ 2^32 的地址空间，其中可预留一段（如 0 ~ 2^10）给一个或多个 I/O 设备。

> **记忆**：MMIO = "外设寄存器假装是内存地址"，CPU 用普通 load/store 就能操作外设。验证时地址解码器（decoder）是否正确响应 MMIO 区域是常见检查点。

### Q44. One-hot 编码的优势

**One-hot 编码**中，每次状态切换有**两个 bit 发生变化**（一个被清 0、一个被置 1）。优势：

- **无需译码（decode）**即可知道当前处于哪个状态；
- 使用**更多触发器（Flip-Flops）**，但**更少的组合逻辑**；
- 在**时序关键路径**上，省掉译码逻辑可能就决定了能否满足时序。

> **记忆**：One-hot 用"面积换时间"——多几个 FF，省一段译码组合逻辑，时序关键路径上常能救命。状态机编码（one-hot / binary / gray）的选择也是验证面试常考点。

### 最重要的 10 条规则

| # | 规则 |
|---|---|
| 1 | RISC 靠"每条指令更简单更快"，CISC 靠"每条程序指令更少"；但现代 CISC 内部也先翻译成微指令执行。 |
| 2 | 哈佛架构数据与指令分存储器/分总线，现代计算机多基于它；冯·诺依曼统一存储。 |
| 3 | 大端把 MSB 放低地址，小端把 LSB 放低地址；跨端序读写是验证必查点。 |
| 4 | SRAM 6T、快、贵，用于 cache；DRAM 1T1C、需刷新、慢、便宜，用于主存。 |
| 5 | 流水线提升吞吐率（throughput）但不降低单条指令延迟（latency）。 |
| 6 | 冒险三兄弟：结构冒险靠"复制资源"，数据冒险靠"乱序 + 前递"，控制冒险靠"分支预测"。 |
| 7 | 流水线总时间 = 首元素走完全部级的时间 + (元素数 − 1) × 单级时间。 |
| 8 | Cache 地址三段式：低位=块内偏移、中间=组索引、高位=tag；相联度越高比较器越大、功耗越高。 |
| 9 | MESI：M=脏私有、E=净私有、S=净共享、I=无效；读需非 I，写需 M/E；RFO=读+作废广播。 |
| 10 | 中断异步（外部硬件）、异常同步（指令触发，分 fault/trap/abort）；TLB 是地址翻译的 cache，命中快、未命中要走页表遍历。 |
