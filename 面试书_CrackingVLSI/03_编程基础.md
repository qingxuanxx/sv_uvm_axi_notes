## 3.1 基本编程概念（Basic Programming Concepts）

> 本章开篇强调：在 SoC 复杂度持续攀升的今天，验证工作越来越偏向软件；验证工程师需要"软硬兼通"，具备硬件与软件接口两侧的知识。因此编程基础几乎是所有验证面试的必考题。

### Q1. 变量：作用域与存储期（static / automatic / local / global）

区分这四类变量需要抓住**两个独立的概念维度**：

| 概念 | 定义 | 划分出的变量类别 |
| --- | --- | --- |
| **作用域（scope）** | 变量在何处可以被访问 | local（局部）vs global（全局） |
| **存储期（storage duration）** | 变量可以被访问多长时间 | automatic（自动）vs static（静态） |

- **局部变量（local）**：作用域有限，只在声明它的代码块内可见。
- **全局变量（global）**：一旦声明，程序中任何位置都可访问。
- **自动变量（automatic）**：生命周期只持续到程序执行离开其所在块/作用域为止（典型：函数内的普通局部变量）。
- **静态变量（static）**：生命周期持续到程序结束，因此全程可访问；但它仍是局部还是全局，由作用域决定（函数内的 static 局部变量作用域仍限于函数内，但值在多次调用之间保留）。

以 SystemVerilog 代码为例：

```systemverilog
class test_class;
    int global_int;           // 类成员，作用域覆盖整个类（全局作用域）；
                              // 生命周期到该类的对象被解引用（de-referenced）时结束
    static int global_static; // static 变量：类内全局作用域 + 生命周期贯穿整个程序，
                              // 即使对象被解引用（甚至从未构造）也依然存在
    void function compute() begin
        static int count;     // 局部 static 变量：仅函数内可见，
                              // 但只有一份拷贝，多次调用 compute() 后值仍保留
        int sum;              // 局部 automatic 变量：仅在 compute() 执行期间存在
                              // （原书写作 "local int sum;"，SV 中局部变量默认即 automatic）
        sum = sum + 1;
        count = count + sum;
    end
endclass
```

> **记忆**：scope 管"看得见看不见"，storage duration 管"活得久不久"。static 只延长寿命、不扩大作用域；automatic 只限定寿命、不影响可见性。SV 的类成员默认 automatic（对象生命周期内存在），而函数内变量默认 automatic；加 static 才能跨调用保留。

### Q2. 内联函数（inline function）

**内联函数**是在调用点被"就地展开"的函数：编译器用函数体代码直接替换函数调用。

- 好处：省去"调用函数 + 从函数返回"的开销，执行更快——尤其当函数体很小且被多处调用时。
- 代价：代码体积增大（每处调用都复制一份函数体）。

C 语言示例（`inline` 关键字）：

```c
inline int max(int a, int b) {
    return a > b ? a : b;
}

main() {
    int a1, a2, a3, b1, b2, b3;
    int c1, c2, c3;
    c1 = max(a1, b1);   // 编译时被替换为 (a1 > b1 ? a1 : b1) 的代码
    c2 = max(a2, b2);
    c3 = max(a3, b3);
}
```

> **注意**：inline 只是"请求"，编译器有权拒绝（如函数体过大、递归函数）。现代编译器会自动内联小函数，inline 更多是给编译器的提示。

### Q3. 正则表达式（regular expression）入门

**正则表达式**是一串具有特殊语法的字符序列，用于在一段文本中匹配或查找其他字符串（或字符串集合），是字符串模式匹配（pattern matching）最强大的工具之一，在 Perl、Python、Tcl 等语言中被广泛使用。

> **记忆**：正则的三要素 = 特殊字符（meta-characters，赋予语法特殊含义）+ 量词（quantifiers，控制"匹配多少次"）+ 锚点（anchors，控制"在什么位置匹配"）。详见 3.3.3 的完整表格。

### Q4. 内存模型：堆（heap）与栈（stack）

| 对比项 | 栈（Stack） | 堆（Heap） |
| --- | --- | --- |
| 存储内容 | 函数创建的临时变量（自动变量） | static 变量、对象等需要长期存在的数据 |
| 管理方式 | **自动管理**：函数每声明一个新自动变量就压栈，函数退出时全部弹出删除 | **需手动管理**：程序员负责分配与释放（支持 GC 的语言由编译器/运行时负责） |
| 分配/释放 | 自动 | malloc/free（C）、new/delete（C++）、new()（SV） |
| 大小 | 有限，耗尽时报 **stack overflow** 错误 | 大小可改变 |
| 访问 | 局部使用 | 通过指针引用，程序中任何位置都可访问 |
| 速度 | 较快 | 稍慢 |
| 问题 | 栈溢出 | **碎片化（fragmentation）**：可用内存散落成不连续块 |

> **注意**：所有局部变量都用栈内存；堆上分配的内存在不用时必须显式释放，否则会内存泄漏（见 3.1.6）。

### Q5. 自增运算符：++a 与 a++

- **++a（前置自增）**：先把 a 的值加 1，再返回引用 a 的值。若赋给变量，用的是 a 自增后的值。
- **a++（后置自增）**：先返回 a 当前的值，再对 a 自增。若赋给变量，用的是 a 自增前的旧值。

```c
a = 10;
b = a++;   // b = 10（a 的旧值），随后 a 变为 11
c = ++a;   // a 先自增为 12，再赋给 c，故 c = 12
```

> **记忆**："++ 在前，先加后用；++ 在后，先用后加"。写进循环和表达式时要格外小心，是面试陷阱高频点（详见 3.3.2）。

### Q6. 内存泄漏（memory leak）

**内存泄漏**：动态分配了内存，却以某种方式丢失了到达该内存的途径（指针），导致该内存永远无法再被使用。

- 在 C/C++ 等语言中，每次分配（如创建对象）都必须释放（调用 destructor/free），否则内存泄漏。
- 在 SystemVerilog、Java 等语言中，语言内部机制负责清理内存（自动垃圾回收），泄漏概率小得多。

> **注意**：SV 没有 destructor，因为语言支持自动垃圾回收（见 3.2.7）。

### Q7. 编译器（Compiler）与解释器（Interpreter）

背景知识：机器只能理解二进制格式的代码，这种机器可读的二进制码叫**机器码（machine code）**。程序员用高级语言（C/C++/Perl/Python）写出的代码叫**源代码（source code）**，必须转换成机器码才能被机器执行。**编译器和解释器都是把源代码转成机器码的程序。**

- **编译器（Compiler）**：一次性把**整个**源代码转换成机器码（生成可执行文件），之后执行的是机器码。例如 C/C++。
- **解释器（Interpreter）**：**逐条语句**扫描翻译，把源代码转成可由另一个程序解释的中间代码；翻译到第一个错误就停止，不再继续处理。例如 Perl、Python（传统意义）。

> **记忆**：编译器"整本翻译再演"，解释器"边翻边演、遇错即停"。Perl 是解释型语言（见 3.3.3）。

### Q8. 静态类型语言与动态类型语言

| 类型 | 类型何时确定 | 特点 | 例子 |
| --- | --- | --- | --- |
| **静态类型（statically typed）** | 编译期（compile time）固定 | 使用变量前必须声明其数据类型 | Java、C、**SystemVerilog** |
| **动态类型（dynamically typed）** | 运行期（execution time）发现 | 使用前无需声明类型，首次赋值时自动确定 | VBScript、Python |

> **记忆**：验证环境里 SV 是静态类型（所以 class 成员都要写类型），而 Perl/Python 脚本是动态类型，写起来更灵活但类型错误要到运行期才暴露。

### Q9、Q26. 栈（Stack）与队列（FIFO）

栈是常用的数据结构。判断下面与 Stack 有关的说法哪个是错的：

1. 对栈只适用 Push 和 Pop 操作 —— 正确
2. 栈实现的是 FIFO —— **错误**
3. 栈对嵌套循环、子程序调用很有用 —— 正确
4. 栈适合算术表达式的求值 —— 正确

> **记忆**：**栈是 LIFO（Last In First Out，后进先出）**，最后压入的变量最先被弹出；FIFO（First In First Out，先进先出）是队列。函数调用、递归都靠栈实现（调用栈 call stack）。

### Q10. Perl 中 use 与 require 的区别

| 对比项 | use | require |
| --- | --- | --- |
| 求值时机 | **编译期**（compile time） | **运行期**（run time） |
| import 函数 | **隐式调用**所加载模块的 import 函数 | 不调用 |
| 参数形式 | 只接受 bareword（裸字） | 可接受 bareword 或表达式 |

> **注意**：因为 use 在编译期处理，加载失败会导致编译失败；require 在运行期处理，可以在程序里按条件动态加载模块。

### Q11. 静态与动态内存分配

> 原书此问只列了问题、未给出单独答案（疑为原书疏漏）。结合本章内容可归纳：
> - **静态分配（static）**：内存大小与位置在编译期决定，生命周期贯穿整个程序（如 static 变量、全局变量）。

### Q12. 预处理器指令（pre-processor directives）

**预处理器指令**是代码中以井号 `#` 开头的行，在编译开始之前由预处理器（pre-processor）先行处理。预处理器改写源代码，生成一份指令被替换后的新源代码，再交给编译器。

典型语法：

```c
#define identifier value
```

预处理器在源代码中每遇到 `identifier`，就把它替换成 `value`，并在编译前生成新源代码。

> **注意**：`#define` 是**文本替换**（宏），不是变量赋值；没有类型检查，是面试常考细节。常见指令还有 `#include`、`#ifdef` 等。

### Q13. C++ 的 using namespace std

- **namespace（命名空间）**：允许程序员把类、对象、函数等实体归组到一个名字之下。
- **std** 是 "standard"（标准）的缩写。**std 命名空间**是存放 C++ 所有内建库例程（如 string、cin、cout、vector 等）的特殊命名空间。
- `using namespace std;` 就是告诉 C++ 编译器：使用标准 C++ 库。

### Q14～Q15. 关键字 const 与 volatile

**const**：告诉编译器，变量/对象一旦定义就不能再改变，程序运行期间不能以任何方式给它赋其他值。

- `int a;`：a 的值在程序不同时刻可以被修改。
- `const int a;`：一旦初始化就不能再修改。

**volatile**（C 语言）：告诉编译器，被声明为 volatile 的变量的值在两次访问之间**可能被外部改变**，因此编译器**不得对 volatile 变量做任何优化**。

被声明为 volatile 后，编译器不能进行以下优化：
- 删除对内存的赋值（memory assignments）
- 把变量缓存到寄存器（caching variables in registers）
- 改变赋值执行的顺序（changing order of execution of assignments）

> **注意**：volatile 主要用于与**内存映射 IO（memory mapped Input Output，硬件）**交互的场合——硬件可能在程序不知情时改变寄存器的值，这是验证工程师做硬件接口代码时最常碰到 volatile 的场景。

### Q16. 指针（pointer）详解

**指针**是值为另一个变量地址的变量。指针存放某个内存位置的直接地址，用星号 `*` 表示指针。

```c
int *p;   // 变量 p 是指针，其值是存放整型变量的内存位置地址
float *f; // 变量 f 是指针，其值是存放 float 变量的内存位置地址
```

深入理解，看下面 C 代码：

```c
int a = 10;
int *b;
int c;
b = &a;   // &a 是变量 a 所在的内存地址
c = *b;   // *b 是"地址 b 处存放的值"，即 a 的值
printf("b=%d and c=%d\n", b, c);
```

假设变量 a 存放在内存地址 `0x1000`（十进制 4096）：
- 指针 b 被赋为 a 的地址，所以 **b 的值 = 4096**
- c 等于 a 的值，所以 **c = 10**

输出为：`b=4096 and c=10`。

> **记忆**：`&` 取地址（address-of），`*` 解引用（dereference，取该地址处的值）。画图理解：a 是一个装着 10 的盒子（地址 0x1000）；b 是一个装着"0x1000"的盒子；*b 就是顺着 b 里的地址找到的那个盒子里的 10。SV 中的 class handle 本质上也是指针/引用（见 3.2.2）。

### Q17. 传值（Pass by Value）与传引用（Pass by Reference）

- **Pass by Value（传值）**：把实参（actual parameter）的**值**复制一份到内存中，赋给一个新变量（形参）。函数内对新变量的任何修改都只影响该函数内部的局部拷贝，**不影响实参的原始值**。
- **Pass by Reference（传引用）**：把实参的**地址**复制一份赋给新变量（形参是指针）。函数内对地址处值的修改**会反映到实参原值上**。占用内存较大的参数（如数组）通常传引用，避免在函数内复制一份。

示例代码：

```c
#include<stdio.h>
void pass_by_value(int a){        // 形参 a 是实参值的一份拷贝
    a = a + 5;
}
void pass_by_reference(int *b){   // 形参 b 是指针，持有实参的地址
    *b = (*b) + 5;                // 修改的是地址处真正的值
}
int main(){
    int c = 15;
    pass_by_value(c);
    printf("1. Value of C is %d\n", c);   // 输出：1. Value of C is 15（未受影响）
    pass_by_reference(&c);
    printf("2. Value of C is %d\n", c);   // 输出：2. Value of C is 20（已被修改）
    return 0;
}
```

> **记忆**：传值 = "复印一份草稿随便改"；传引用 = "把原件的地址告诉对方，对方直接改原件"。C 语言只有传值，传引用是通过传指针地址模拟出来的；C++/SV 才真正支持引用/句柄语义。

### Q18. NULL 指针的值与大小

```c
int *a = NULL;
```

- **NULL 指针的值是 0**。
- 指针的值是地址，所以**指针的大小取决于机器**：32 位机器上指针为 **4 字节**，64 位机器上指针为 **8 字节**（与所指向的数据类型无关，见 3.3.2 的 sizeof 题）。

### Q19. 链表（linked list）

**链表**是一种数据结构，由一组节点（node）共同表示一个序列。最简单的形式中，每个节点由**数据（data）**和**指向序列中下一个节点的引用/链接（link）**组成。

链表有以下几种类型：
1. **线性链表 / 单向链表 / 单链表**（Linear / One Way / Singly Linked List）

3. **循环链表**（Circular Linked List）

> 链表的具体 C 实现（创建、头插、尾插、按位置插入、删除）是高频手写题，完整代码见 3.3.2。

### Q20～Q21. 时间复杂度与空间复杂度（Big O）

**时间复杂度**简单说就是"某个算法要跑多久"——算法运行时间作为输入规模（input string length）的函数。在动手写算法/程序前估算运行时间很有意义，可以判断资源利用是否高效：程序执行时间越长，消耗的机器资源越多、成本越高。

**Big O 表示法**：忽略系数和低阶项。例如某算法时间复杂度算得 5n⁴ + 6n² + 1，Big O 记为 **O(n⁴)**。

由于相同规模的不同输入下算法表现可能不同，复杂度分**最好（Best）、平均（Average）、最坏（Worst）**三种情况。通常我们关心平均和最坏情况，很少关心最好情况。

**常见算法的最坏情况时间复杂度**（N = 列表大小）：

| 算法 | 最坏情况时间复杂度 |
| --- | --- |
| 线性查找（Linear Search） | O(N) |
| 二分查找（Binary Search） | O(log N) |
| 插入排序（Insertion Sort） | O(N²) |
| 归并排序（Merge Sort） | O(N·log N) |
| 桶排序（Bucket Sort） | O(N) |

**空间复杂度**概念与时间复杂度类似，只是它表示**执行程序/用某算法解决问题所需的总存储空间（内存）**，同样用 Big O 表示：

| 算法 | 空间复杂度 |
| --- | --- |
| 线性查找（Linear Search） | O(1) |
| 二分查找（Binary Search） | O(1) |
| 插入排序（Insertion Sort） | O(N) |
| 归并排序（Merge Sort） | O(N) |
| 桶排序（Bucket Sort） | O(N) |

> **记忆**：查找类（线性/二分）几乎不占额外空间 O(1)；排序类中插入排序原地 O(N)（若算上输入本身），归并、桶排序需要额外 O(N) 空间。二分查找的快（O(log N)）来自每次砍半，前提是数据**有序**。

### Q22. 位运算 & 与逻辑运算 &&

- **`&` 是按位与（bitwise AND）**：对每个 bit 逐位做与运算，返回位值。
- **`&&` 是逻辑与（logical AND）**：作用于布尔值 true(1)/false(0)，返回布尔值。

```c
// 位运算：a=10（4'b1010），b=6（4'b0110）
// a & b = 4'b0010 = 2
if (a == 10 && b == 6)  // 逻辑运算：两个布尔表达式都为真，整体为 true
```

> **注意**：位运算无短路特性（所有位都参与计算），逻辑运算有短路特性（`&&` 左侧为假则右侧不再求值）。

### Q23～Q25. 结构体（struct）与联合体（union）的内存分配

- **struct（结构体）**：分配足以存储**所有**字段/成员的空间——第一个成员从结构体起始位置存放，第二个紧接其后，依此类推。所有成员可同时被引用。
- **union（联合体）**：只分配足以存储**最大的那个成员**的空间，所有成员**共享同一块空间**。因为 union 同一时刻只能使用其中一种成员（不同于 struct 中所有成员都可引用）。

示例：

```c
struct ID {
    int  IntID;      // 4 字节
    char CharID[8];  // 8 字节
};
// struct ID 共分配 12 字节（4 + 8）

union ID {
    int  IntID;
    char CharID[8];
};
// union ID 只分配 8 字节（取最大成员 char[8]）
```

> **记忆**：struct = "各住各屋"（空间相加）；union = "合住一屋"（空间取最大）。实际工程中还要考虑内存对齐（padding），但原书此题按 4+8=12 计算。

### Q27～Q28. 内核（kernel）、UNIX 与 Linux

**Kernel（内核）**：管理来自软件的输入/输出请求、并把请求翻译成 CPU 指令或其他电子指令的计算机程序。

**UNIX**：一种操作系统（像 Windows 一样），是多用户（multi-user）、多任务（multi-tasking）的系统，用于服务器、台式机和笔记本。由三部分组成：**Kernel（内核）、Shell（外壳，用户与内核之间的接口）、Program（程序）**。

**UNIX 与 Linux 的区别**：

| 对比项 | Linux | UNIX |
| --- | --- | --- |
| 开源 | 免费、开源（open source） | 不同版本按供应商定价 |
| 开发方式 | 开源社区开发 | 各厂商商业发行 |
| 发行版例子 | Ubuntu（Linux 发行版） | Solaris（UNIX 发行版） |

### Q29～Q31. Perl 语言入门

**Perl 全称**：Practical Extraction and Reporting Language（实用摘取与报告语言）。

**Perl 是解释型语言**，意味着：它一次一条语句地扫描并翻译源代码，把源代码转换成可被另一个程序解释的中间代码；它不会像编译器那样把整个源代码转换成二进制代码；**Perl 会一直翻译，直到遇到第一个错误才停止后续处理**。

**Perl 的三种数据类型**：

| 类型 | 前缀符号 | 说明 |
| --- | --- | --- |
| 标量（Scalar） | `$` | 简单变量，可以是数字、字符串或引用 |
| 数组（Array） | `@` | 标量的有序列表，下标从 0 开始 |
| 哈希（Hash） | `%` | 无序的键/值（key/value）对集合，用键作为下标访问 |

### Q32～Q33. Cron Job 与 rsync

**Cron Job**：操作系统里基于时间的任务调度（time based job scheduling），允许你按指定的时间、日期、天数、间隔等周期性自动运行作业。

> 例子：假设用户有一个计算磁盘上每人磁盘空间占用情况的 Shell 或 Perl 脚本，在 UNIX/Linux 中为其设置 Cron job 并指定频率/时间，脚本就会按计划自动运行，无需用户每次手动执行。（具体 crontab 命令见 3.3.1）

**rsync**：全称 "Remote Sync"（远程同步），是跨磁盘、网络、服务器、机器复制或同步文件/目录的常用命令。
- 只传输文件中**发生改变的部分**，从而最小化需要复制的数据量；
- 收发数据时使用压缩/解压方法，**占用带宽更少**；
- 最常见的用途：在两台机器之间做数据备份和磁盘镜像（mirror）。

### Q34～Q38. 其他零散高频考点

**1）C 变量名能包含字母数字以及特殊字符吗？——不能（False）**。C 变量名只能由字母、数字、下划线组成，且不能以数字开头。

**2）`'\0'` 字符的用途**：终止空字符（terminating null character），用于标记字符串的**结尾**。C 字符串实际是字符数组，以 `\0` 结束。

**3）什么是二叉树（binary tree）**：链表概念的扩展。二叉树每个节点有两个指针：**左指针和右指针**，每侧又可以继续分支形成更多节点，且每个节点同样拥有两个指针。

**4）C 中如何生成随机数**：使用 `rand()` 函数，并包含头文件 `<stdlib.h>`。随机数生成对测试很重要——用大量不同的输入测试程序/代码，验证其在各种输入下都能正确工作；`rand()` 帮助随机化输入条件、生成随机输入。

**5）正则表达式的特殊字符、量词、锚点**（详见 3.3.3 的完整表格）：
- **特殊字符（Special Characters）**：给正则搜索语法赋予特殊含义的元字符，如 `\`、`^`、`$`、`()`、`[]`、`|`、`&`。
- **量词（Quantifiers）**：规定"匹配前面那个正则多少次"，如 `*`、`+`、`?`、`{}`。
- **锚点（Anchors）**：规定"在哪儿匹配"，允许用户指定文本/模式搜索的位置，如 `^`、`$`、`<`、`>`。

## 3.2 面向对象编程（Object Oriented Programming，OOP）

> OOP 概念与 SystemVerilog 的 class 机制一一对应，是验证工程师理解 SV 验证环境（UVM 等）的基石，本章节请重点掌握。

### Q39. 类（class）与对象（object）

- **类（class）**：一组可以归并在一起的**属性（attributes）**与**相关行为（behavior）**。属性用类的数据成员（data members）表示，行为用方法（methods）表示。
- **对象（object）**：类的实例（instance），代表一个具有属性和行为的真实实体。

> 例子：Animal 可以表示为一个类；dog、cat 等不同动物就是 Animal 类的对象。

> **记忆**：类 = 图纸（模板），对象 = 按图纸造出来的实物。SV 中"声明类变量"只是拿到一个 handle，`new()` 之后才是真正的对象（见 3.2.2）。

### Q40～Q41. C++ 与 SystemVerilog 中 class 与 struct 的区别

**C++ 中**：struct 最初由 C 定义，用于把不同类型的数据归组以实现某个功能；C++ 把这个归组扩展到可以包含函数。class 同样是可归组不同数据类型和函数的类型。

| C++ 对比项 | class | struct |
| --- | --- | --- |
| 默认访问级别 | **private（私有）** | **public（公有）** |
| 其他 | 功能上几乎一样 | 功能上几乎一样 |

> **记忆**：C++ 中 class 与 struct 的唯一实质区别就是默认访问权限不同——class 默认 private，struct 默认 public。

**SystemVerilog 中**：class 和 struct 都用于按功能定义数据类型的组合，但有本质区别：

| SV 对比项 | struct | class |
| --- | --- | --- |
| 类型性质 | **整型（integral type）**，声明即分配内存 | **动态类型（dynamic type）**，声明只得到一个指向 null 的 class handle |
| 内存分配时机 | 声明时 | 创建实际对象时才分配（`new()`） |

```systemverilog
MyClass obj;   // 只声明：obj 是一个 handle，指向 null，尚无内存
obj = new();   // 创建对象：此刻才真正分配内存
```

> **注意**：SV 面试常考"声明 class 变量 = 只拿 handle"，未 new 就访问成员会报 null 访问错误。这个"handle"概念其实就是 3.1.15 指针思想的面向对象版。

### Q42. 访问控制：public / private / protected

类成员的三种访问属性：

| 访问属性 | 类内访问 | 类外访问 | 派生类（子类）中可见 |
| --- | --- | --- | --- |
| **private（私有）** | ✅ | ❌ | ❌ |
| **public（公有）** | ✅ | ✅ | ✅ |
| **protected（受保护）** | ✅ | ❌ | ✅ |

> **记忆**：private 最严（只有本类自己能用），protected 放宽给"子孙类"，public 对所有人开放。protected 与 private 的区别仅在于"派生类里能不能看到"。

### Q43. 多态（Polymorphism）

**多态**指"能呈现多种形态"的能力。在 OOP 语境下，指一个实体**在运行期能引用不同类的对象**的能力。

- SystemVerilog 中：通过**继承（inheritance）**与**虚函数（virtual function）**实现；
- C++ 中：还通过**函数重载与运算符重载**实现。
- 根据对象的具体类型，会从对应类调用合适的方法。

> **记忆**：多态 = "一个句柄，多种形态"。基类句柄指向派生类对象，调用 virtual 方法时动态分派（dynamic dispatch）到派生类的实现——UVM 中 factory 机制正是基于此。

### Q44. 方法重载（Overloading）与方法重写（Overriding）

**方法重载（overloading）**：同名函数可以定义多次，每次使用不同的参数集合。调用时根据传入参数的类型和数量自动选择正确的定义。例如 `add()` 可以有三个版本：

```systemverilog
function add(int operand1, int operand2);              // 版本1：两个 int
function add(int operand1, int operand2, int operand3); // 版本2：三个 int
function add(float operand1, float operand2);           // 版本3：两个 float
```

**方法重写（overriding）**：继承类（派生类）重新定义基类的虚方法。大多数 OOP 语言支持重写。

> **注意（SV 与 C++ 的关键差异）**：与 C++ 不同，**SystemVerilog 不支持方法重载**；SV 只支持针对虚方法和派生类的方法重写。这是 SV 面试高频考点！

SV 重写示例：

```systemverilog
class BaseClass;
    int a, b;
    virtual bit function compare();   // 基类声明为 virtual
        if (a == b) return 1;
    endfunction
endclass

class DerivedClass extends BaseClass;
    int c;
    function compare();               // 派生类重写（override）
        if ((a == b) && (a == c)) return 1;
    endfunction
endclass
```

| 对比项 | 重载 overloading | 重写 overriding |
| --- | --- | --- |
| 定义位置 | 同一类内 | 基类 → 派生类 |
| 函数签名 | 同名、**不同参数** | 同名、同参数 |
| 关键字 | 无 | 基类方法需 virtual |
| C++ 支持 | ✅ | ✅ |
| SystemVerilog 支持 | ❌ | ✅ |

### Q45. 运算符重载（operator overloading）

**运算符重载**是多态的一种特例：可以重新定义（重载）内建的运算符，使程序员也能对用户自定义类型使用这些运算符（如让两个 class 对象可以相加）。

- **C++ 支持**运算符重载；
- **SystemVerilog 不支持**。

C++ 示例：重载 `+` 使两个 Testclass 对象可以相加，实现把两个对象的数据成员相加并赋给结果对象：

```cpp
#include <iostream>
class Testclass {
public:
    int a;
    int b;
    Testclass operator +(const Testclass &obj);
};

Testclass Testclass::operator +(const Testclass &obj2) {
    Testclass tmp_obj = *this;        // 拷贝当前对象（this 指向的对象）
    tmp_obj.a = tmp_obj.a + obj2.a;   // 数据成员逐项相加
    tmp_obj.b = tmp_obj.b + obj2.b;
    return tmp_obj;
}

int main(void) {
    Testclass obj1, obj2, obj3;
    obj1.a = 1; obj1.b = 1;
    obj2.a = 2; obj2.b = 2;
    obj3.a = 0; obj3.b = 0;
    obj3 = obj1 + obj2;               // 调用重载的 + ：3 3
    std::cout << obj3.a << "  " << obj3.b << "\n";   // 输出：3  3
    return 0;
}
```

> **注意**：运算符重载是 C++ 独有的高频题；SV 中请用方法实现同样功能（这也是 SV 验证环境中常见编码风格差异）。

### Q46～Q47. 构造函数（constructor）与析构函数（destructor）

**构造函数（constructor）**：类的特殊成员函数，**每当创建类的一个实例时自动被调用**。
- C++：与类同名（如 `Testclass()`）。
- SystemVerilog：实现为 `new()` 函数。

**析构函数（destructor）**：类的特殊成员函数，**每当对象超出作用域时自动被调用**。
- C++：与类同名、前面加波浪号 `~`（如 `~Testclass()`）。
- SystemVerilog：**没有析构函数**，因为语言支持自动垃圾回收（见 3.1.6）。

> **记忆**：constructor = "出生时自动执行"；destructor = "死亡时自动执行"。SV 只需 new()，C++ 需要成对写构造/析构（负责释放动态资源，避免泄漏）。

### Q48. 组合（composition）与继承（inheritance）

- **组合（composition）**：两个类之间是 **"has-a"（有一个）** 关系。当一个类实例化了另一个类的对象时，就是 has-a 关系，这个性质叫组合。
- **继承（inheritance）**：两个类之间是 **"is-a"（是一个）** 关系。当一个类从另一个类派生时，就是 is-a 关系，这个性质叫继承。

> 例子：基类 car（汽车），Ford 类从 car 派生——关系是 "is-a"（Ford 是一辆 car）；若 Ford 类内部有一个 engine（引擎）类的对象，则这个关系是 "has-a"（Ford 拥有一台 engine）。

| 关系 | 含义 | 例子 |
| --- | --- | --- |
| 继承 inheritance | is-a（是一个） | Ford is a Car |
| 组合 composition | has-a（有一个） | Ford has an Engine |

> **记忆**：判断用继承还是组合，就问一句话："它是它吗？"（is-a → 继承）；"它有它吗？"（has-a → 组合）。组合优先于继承是现代 OOP 的设计原则之一。

### Q49. 浅拷贝（shallow copy）与深拷贝（deep copy）

- **浅拷贝（shallow copy）**：创建新对象，字段值与原对象完全一致；但如果某字段是**对其他对象的引用**，则只复制**引用地址（handle）**本身。
- **深拷贝（deep copy）**：创建新对象，字段值与原对象完全一致；如果对象引用了其他对象，则**被引用对象的所有值也被一并复制**，而不只是复制内存地址或 handle（所以叫"深"）。

示例：有两个类 A 和 B：

```systemverilog
class A;
    int a;
    int b;
endclass

class B;
    int c;
    A objA;    // B 引用了 A 的对象
endclass
```

- 若在类 B 中实现**浅拷贝**：把 B 复制到新对象时，只复制 `objA` 的 handle（地址）。
- 若是**深拷贝**：A 的所有值（数据成员 a 和 b）也被完整复制，而不是只复制 `objA` 的 handle。

> **记忆**：浅拷贝"共享同一份被引用的对象"，深拷贝"连被引用的对象也各自复制一份"。SV 中默认 `=` 对 class 是句柄赋值（类似浅拷贝），深拷贝需要自己写 copy 函数（UVM 的 `copy()` 即为此设计）。

### Q50. 虚函数（virtual function）

**虚函数**是声明在基类中、可以被派生类重新定义的成员函数。创建虚函数的方法：在基类的函数声明前加关键字 **virtual**。这种在派生类中重新定义基类函数的方式也叫**方法重写（method overriding）**。

```systemverilog
class BaseClass;
    virtual bit function compare();   // virtual 声明，派生类可重写
    ...
endclass
```

> **记忆**：virtual 是"多态的开关"——只有 virtual 方法才支持运行期动态分派；非 virtual 方法即使通过派生类对象调用，绑定的仍是基类版本。

### Q51. 多重继承（multiple inheritance）

**多重继承**是部分 OOP 语言的特性：一个对象/类可以从**多个**父对象/父类继承特征与功能。与之相对的是**单继承（single inheritance）**：只能从一个父类继承。

> **注意**：**C++ 支持多重继承，SystemVerilog 不支持**（SV 只支持单继承 + interface/多重接口）。又是 C++ 与 SV 差异的高频考点。

### Q52. 抽象类（abstract class）

**抽象类**是包含一个或多个**抽象方法（abstract method）**的类。抽象方法指"只声明、没有实现"的方法。抽象类**不能被实例化**，要求子类为抽象方法提供实现。

- SystemVerilog 中：类名前面加 **virtual** 关键字即成为抽象类。

示例：

```systemverilog
virtual class BaseShape;                       // virtual class = 抽象类
    virtual function int get_num_edges();      // 只有声明、没有实现
    endfunction
endclass

class Rectangle extends BaseShape;
    function int get_num_edges();              // 子类必须提供实现
        return 4;
    endfunction
endclass
```

> **记忆**：抽象类 = "只画框、不填内容"的模板，强制子类实现。SV 里 `virtual class` 与 `virtual function` 两个 virtual 含义不同：前者是抽象类标记，后者是虚方法标记。

### Q53. 类内静态方法（static method）

**静态方法（static method）**：在类内用 **static** 关键字定义的方法。

- **可以不创建类的对象就直接使用**；
- 即使创建了该类的多个对象，**静态方法也始终只有一份**，属于所有对象共享。

> **注意**：static 方法与 3.1.1 的 static 变量思想一致——"一份拷贝、全局共享、不依赖对象实例"。SV 中 static 方法内不能访问非 static 成员（因为它没有 this）。

### Q54. this 指针

**this 指针**是一个特殊指针，在类作用域内用来引用**当前对象（current object）**。

```cpp
Testclass tmp_obj = *this;   // *this 就是"当前对象本身"，解引用 this 得到对象
```

> **记忆**：this = "我自己"。在方法里区分形参与成员同名变量、或返回当前对象时用它。SV 的 class 方法中也存在 this（句柄），UVM 组件里常见 `this.xxx` 的写法。

### Q55. 类型转换（type conversion）与类型强制转换（type casting）

两者都是把一种数据类型改变成另一种数据类型的方式，区别在于是隐式还是显式：

- **类型转换（type conversion）**：**隐式**转换（编译器自动做）。
- **类型强制转换（type casting）**：**显式**转换（程序员明确写出）。

```c
int a;
double b;
a = b;          // 隐式转换：把 double 赋给 int，编译器自动做（可能有精度损失）

double a = 2.2;
double b = 3.3;
int c = (int)a + (int)b;   // 显式强制转换：(int) 把 double 截断成 int
// 小数部分被截断，结果 c = 2 + 3 = 5
```

> **注意**：C 的强制转换是"截断"（truncate）而非四舍五入；SV 中类型转换用 `$cast()`（用于句柄向下转型）或赋值转换，是验证面试常见延伸考点。

#### Q65. 大小端（Endian）检测

假设 32 位机器。无符号整数 1 在两种字节序下的内存布局（低地址 → 高地址）：
- **Little Endian（小端）**：`01 00 00 00`（最低有效字节 LSB 存于最低地址）；
- **Big Endian（大端）**：`00 00 00 01`（最高有效字节 MSB 存于最低地址）。

检测代码：把整数地址强转成 `char*`，看第一个字节是否为 1。

```c
#include <stdio.h>
int main() {
    unsigned int i = 1;
    char *c = (char *)&i;   // 取 i 的最低地址字节
    if (*c) printf("Little Endian \n");   // 第一个字节是 1 → 小端
    else printf("Big Endian \n");         // 第一个字节是 0 → 大端
    return 0;
}
```

> **记忆**："小端" = 低字节在低地址（像我们读十进制数从左到右，但内存反着来）；x86 是小端，网络字节序是大端。验证中跨端传输数据（如总线协议字节序）经常考到。

#### Q66. 自增陷阱：a=10; b=a++; c=++a;

```c
a = 10;
b = a++;   // 后置：先赋值再自增 → b = 10，随后 a = 11
c = ++a;   // 前置：先自增再赋值 → a 从 11 变为 12，c = 12
```

**答案：b = 10，c = 12**。后置自增的赋值发生在自增之前，所以 b 看到的是自增前的 a；前置自增先自增，所以 a 从 11（b=a++ 之后 a 已变为 11）再加到 12，c 得到 12。

#### Q67. 全局与局部同名变量

```c
#include <stdio.h>

int main() {
    int xyz = 20;    // 局部变量 xyz（与全局同名，遮蔽 shadowing）
    printf("%d", xyz);   // 输出：20
    return 0;
}
```

**答案：输出 20**。xyz 同时有全局和局部定义；在函数内打印时，作用域更近的**局部变量**生效（局部遮蔽全局）。

#### Q68. 类型重解释：把 int 按 float 读

```c
int main() {
    int x = 4;
    float y = *(float *)&x;   // 把 x 的地址当 float 指针，再解引用
    return 0;
}
```

**答案：一个非常小的值（very small value）**，部分编译器可能显示为 0。

原理：`(float *)&x` 告诉编译器"该地址处存的是一个 float"；`*(float *)&x` 表示"该地址处的 float 值"。float 与 int 的存储格式不同——float 中 **bit[31] 是符号位，bit[30:23] 是指数（exponent），bit[22:0] 是尾数（fraction）**。整数 4 的位模式是 `00000000000000000000000000000100`，按 float 格式解释时指数为 0，是一个非规格化（denormal）的极小值，因此结果非常小（约 5.6e-45）。

> **注意**：这就是"数据只是一串 bit，解释方式决定意义"的经典考题，也提醒我们在验证中做类型转换/强制转换时要清楚位模式（见 3.2.15）。

#### Q69. switch 穿透（fall-through）陷阱

```c
#include<stdio.h>
int main() {
    int i = 0;
    for (i = 0; i < 20; i++) {
        switch (i) {
            case 0: i += 5;
            case 1: i += 2;
            case 5: i += 5;
            default: i += 4; break;   // 唯一的 break
        }
        printf("%d\n", i);
    }
    return 0;
}
```

**答案：输出 16 和 21**。

逐轮推演：
- i = 0 进入 `case 0`：i += 5 → i = 5。**`case 0` 后面没有 break**，继续执行 `case 1`：i += 2 → 7；继续 `case 5`：i += 5 → 12；继续 `default`：i += 4 → **16**，遇到 default 后的 break 才跳出 switch。打印 **16**。
- for 循环的 i++ 使 i 变为 17；switch(17) 没有匹配 case，直接走 `default`：i += 4 → **21**，打印 **21**。
- for 循环 i++ → 22 ≥ 20，循环结束。

> **注意**：C 的 switch 是"跳转标签 + 穿透"模型——case 后**没有 break 就会一路掉下去**（fall-through）执行后续所有 case 直到 break 或 switch 结束。SV 的 case 无此行为，这是跨语言写代码时最容易踩的坑。

#### Q70. 递归求阶乘（n ≥ 0）

```c
int factorial(int x) {
    if ((x == 0) || (x == 1)) return 1;      // 递归出口
    else return (x * factorial(x - 1));       // 递归：n! = n × (n-1)!
}
```

#### Q71. 递归生成斐波那契数列

```c
int fibonacci(int num) {
    if ((num == 0) || (num == 1)) return num;               // 出口：F(0)=0, F(1)=1
    else return (fibonacci(num - 1) + fibonacci(num - 2));  // F(n) = F(n-1) + F(n-2)
}
```

> **注意**：递归两个要素——**出口条件（base case）** 和 **递推公式**。斐波那契朴素递归是指数复杂度（大量重复计算），工程上应改用迭代或记忆化，但面试手写递归考察的是思路清晰。

#### Q73～Q78. 链表（linked list）完整实现

链表的适用场景（何时优先用链表）：**不知道要存储的数据量时**。例如员工管理系统——可以方便地添加新员工记录（新增节点 = 动态内存分配）、删除老员工记录（删除节点）、编辑员工记录（编辑节点内数据）。数组的大小固定，链表则可动态增长。

统一的数据结构声明（下列 5 个函数共用）：

```c
struct node;
typedef struct node NODE;    // 节点类型
typedef int Element;         // 元素类型
typedef NODE *LINK;          // 指向节点的指针

struct node {                // 节点 = 数据 elem + 指向下一个节点的指针 next
    Element elem;
    LINK next;
};

typedef struct {             // 链表头：记录大小 size 与起始节点指针 start
    int size;
    LINK start;
} ListHead;
```

**1）创建单链表**——创建表头、把 size 初始化为 0、把 start 指向 NULL（创建时空链表）：

```c
ListHead createList() {
    ListHead h;
    h.size = 0;
    h.start = NULL;
    return h;
}
```

**2）在表头插入元素**——动态分配新节点、赋元素值、新节点 next 指向原表头指向的节点、更新 size 和 start：

```c
ListHead InsertElementAtHead(Element e, ListHead h) {
    LINK nl = (LINK) malloc(sizeof(NODE));   // 动态分配新节点
    nl->elem = e;                            // 给新节点赋元素值
    nl->next = h.start;                      // 新节点指向原第一个节点
    h.start = nl;                            // 表头 start 指向新节点
    h.size++;                                // size 加 1
    return h;
}
```

**3）在表尾插入元素**——新节点 next 置 NULL；链表为空则 start 直接指向新节点，否则遍历到最后一个节点再挂接：

```c
ListHead InsertElementAtTail(Element e, ListHead h) {
    LINK temp;
    LINK nl;
    nl = (LINK) malloc(sizeof(NODE));
    nl->elem = e;
    nl->next = NULL;                     // 新节点是表尾
    if (h.start == NULL)                 // 空链表：直接作为第一个节点
        h.start = nl;
    else {
        temp = h.start;
        while (temp->next != NULL)       // 遍历到最后一个节点
            temp = temp->next;
        temp->next = nl;                 // 原表尾指向新节点
    }
    h.size++;
    return h;
}
```

**4）在位置 pos 插入元素**——pos 超过链表大小则报错；pos=0 等同头插；否则遍历到 pos 之前的节点，把新节点插入中间（注意 count 从 0 开始）：

```c
ListHead InsertAtPos(Element e, ListHead h, int pos) {
    LINK temp;
    LINK nl;
    nl = (LINK) malloc(sizeof(NODE));
    nl->elem = e;
    int count = 0;
    if (pos > h.size) {                      // 非法位置
        printf("Error: Wrong position \n");
        return h;
    }
    if (pos == 0) {                          // 头插
        nl->next = h.start;
        h.start = nl;
    } else {
        for (temp = h.start; count < (pos - 2); temp = temp->next, count++);  // 走到 pos 前一个节点
        nl->next = temp->next;               // 新节点指向 pos 处的原节点
        temp->next = nl;                     // pos 前一个节点指向新节点
    }
    h.size++;
    return h;
}
```

**5）删除元素**——先判空；非空则遍历找元素 e 所在的节点，把前一个节点的 next 指向被删节点的 next，再 free（注意头节点特判）：

```c
ListHead DeleteElement(Element e, ListHead h) {
    LINK cur, prev;
    cur = h.start;
    if (cur == NULL) {                       // 空链表，无需删除
        printf("Empty List \n");
        return h;
    }
    while (cur != NULL) {
        if (cur->elem == e) {
            if (cur == h.start)              // 删除的是头节点
                h.start = cur->next;
            else                             // 前一个节点跳过被删节点
                prev->next = cur->next;
            free(cur);                       // 释放内存（防泄漏，见 3.1.6）
            h.size--;
            break;
        }
        prev = cur;                          // 记录前驱
        cur = cur->next;                     // 继续遍历
    }
    return h;
}
```

> **记忆（链表操作口诀）**：插入 = "先接新后改旧"（先让新节点 next 指向目标，再改前驱的 next）；删除 = "前驱跳过被删者，再 free"。注意边界：空链表、头节点、pos 越界。

#### Q79. foreach 中修改循环变量会写回数组

```perl
my @value_array = ("Index0","Index1");
my $value;
foreach $value (@value_array) {
    $value =~ s/Index//;    # 把 $value 中的 "Index" 替换为空

```

**答案：输出 `0 1`**。在 `foreach` 中，循环变量 `$value` 是数组元素的**别名（alias）**，对它的替换会直接写回数组，所以数组变成了 ("0", "1")。

#### Q80. for 循环中修改循环变量不影响数组

```perl
my @value_array = ("Index0","Index1");

for (my $i = 0; $i < @value_array; $i++) {
    $value = $value_array[$i];   # $value 是元素的拷贝
    $value =~ s/Index//;         # 只修改拷贝
}
print "@value_array \n";
```

**答案：输出 `Index0 Index1`**。`$value` 只是数组元素的**拷贝（局部于 for 循环）**，修改不影响数组本身。

> **对比记忆**：Perl 的 `foreach` 循环变量是"别名"（改了就写回），`for` 按下标访问则是"拷贝"（改了不写回）。这是 Perl 面试的经典区分点。

#### Q81. -w 与 use strict 的作用

- **`-w`**：开启警告（warnings），提示脚本中可能被误解的语法（potential to misinterpret syntax）。**好的代码理想情况下不应有任何警告**。
- **`use strict`**：检查脚本中变量的**定义与使用**。这比 -w 更严格一步；脚本中出现任何**含糊或不安全（ambiguous or unsafe）**的命令时，**strict 会直接停止脚本执行**，而不仅仅是给出警告。

> **记忆**：-w = 警告（提醒），strict = 拦截（报错并停止）。生产级 Perl 脚本的标准写法是 `use warnings; use strict;`。

| `^` | 从字符串/行的开头匹配 |
| `$` | 在字符串/行的结尾匹配 |
| `<` | 在单词开头匹配 |
| `>` | 在单词结尾匹配 |
| `\b` | 单词与非单词之间的边界 |
| `\B` | 单词与非单词之间的**非**边界 |

> **记忆**：量词是"多少次"（\* + ? {}），锚点是"哪儿"（^ $ < > \b），特殊字符是"是什么/怎么组合"（\\ . [] () | &）。grep 里的 `^cat`、`cat$` 用的就是锚点（见 3.3.1）。

#### Q89～Q93. 文件过滤正则填空

下面程序从 input_file.txt 读每一行，若 `$_` 匹配正则 `__?__` 就把该行写入 output_file.txt：

```perl
#!/usr/bin/perl
use warnings;
use strict;
my $input_file = "input_file.txt";
my $output_file = "output_file.txt";
my @input_array;
open (OUTPUT_FILE, '>', $output_file) or die "Cannot Open $output_file file for writing\n$!\n";
open (INPUT_FILE, '<', $input_file) or die "Cannot Open $input_file for reading\n$!\n";
while (<INPUT_FILE>) {
    if ($_ =~ /__?__/) {       # 待填空的正则
        print OUTPUT_FILE $_;
    }
}
close INPUT_FILE;
close OUTPUT_FILE;
```

| # | 需求 | 答案 |
| --- | --- | --- |
| 183 | 只含小写字母（a-z）的行 | `^([a-z]+)$` |
| 184 | 只含小写或大写字母（a-z 或 A-Z）的行 | `^([a-zA-Z]+)$` |
| 185 | 只含字母（大小写）或数字（0-9）的行 | `^([a-zA-Z0-9]+)$` |
| 186 | 含 `$` 的行 | `\$` |
| 187 | 只含 `\` 或 `$` 的行 | `^([\\\$]+)$` |

> **注意**：`^` 和 `$` 锚定整行（`^...$` = 整行必须完全匹配）；`\$` 转义让 `$` 变成字面量；`[\\\$]` 字符类里同时匹配字面量反斜杠和美元符。

#### Q94～Q96. chop() 与 chomp()

| 函数 | 行为 | 返回值 |
| --- | --- | --- |
| `chop()` | 删除字符串的**最后一个字符** | 返回被删除的那个字符 |
| `chomp()` | 删除字符串末尾的**输入记录分隔符**（默认是换行符 `\n`，由变量 `$/` 即 `$INPUT_RECORD_SEPARATOR` 决定） | 返回被删除的**字符个数** |

```perl
my $example_1 = "chop_example";
my $example_2 = "chop_example";
chop($example_1);            // 删掉末尾的 "e"
my $b = chop($example_2);    // 删掉 "e"，并把返回的字符 "e" 赋给 $b
print "$example_1 AND $b\n"; // 输出：chop_exampl AND e
```

```perl
my $example_1 = "chomp_example\n";
my $example_2 = "chomp_example\n";
chomp($example_1);            // 删掉末尾换行符
my $b = chomp($example_2);    // 删掉换行符，返回删除的字符数 1
print "$example_1 AND $b\n";  // 输出：chomp_example AND 1
```

> **记忆**：chop 删"最后一个字符"（返回字符本身）；chomp 删"末尾换行"（返回个数）。读文件行时用 chomp 去 \n 是标准操作，比 chop 安全（不会误删有效字符）。

### 最重要的 10 条规则

| # | 规则 | 说明 |
| --- | --- | --- |
| 1 | 区分作用域（scope）与存储期（storage duration） | local/global 由作用域决定，automatic/static 由存储期决定；static 延长寿命但不扩大作用域 |
| 2 | 栈自动管理、容量有限；堆手动管理、大小可变 | 栈溢出（stack overflow）、堆碎片化（fragmentation）是各自典型问题 |
| 3 | `++a` 先自增后取值，`a++` 先取值后自增 | 前置/后置语义是表达式与循环陷阱的高频考点 |
| 4 | 动态分配的内存必须释放 | C++ 靠 destructor/free，否则 memory leak；SV/Java 靠自动垃圾回收 |
| 5 | 静态类型编译期定型，动态类型运行期发现 | C、Java、SV 是静态类型；Python、VBScript 是动态类型 |
| 6 | 栈是 LIFO（后进先出），不是 FIFO | FIFO 是队列的语义，两者不可混用 |
| 7 | 指针大小由机器位数决定，与指向类型无关 | 32 位 = 4 字节，64 位 = 8 字节；NULL 指针值为 0 |
| 8 | C++ 中 class 默认 private、struct 默认 public；SV 中 struct 是整型静态分配、class 是动态类型（handle + new()） | 声明 class 变量 ≠ 创建对象，必须先 new() |
| 9 | SV 支持重写（overriding）与多态（virtual），不支持方法重载与运算符重载；C++ 两者都支持 | 跨语言差异是面试高频陷阱；抽象类 = `virtual class` |
| 10 | Perl 的 foreach 循环变量是数组元素别名（修改写回数组），for 下标访问是拷贝（修改不影响数组） | 同理：s/// 只替换第一个匹配，加 g 才全局替换；chop 删末字符、chomp 删末换行 |
